# Transformer 注意力加速硬件架构研究综述

## 1. 全局数据流与阵列架构  
- **数据流策略**：现代Transformer加速器常采用二维矩阵运算阵列（Systolic Array），并可配置为不同数据流模式：重量驻留（Weight-Stationary, WS）、输出驻留（Output-Stationary, OS）或行驻留（Row-Stationary）等【11†L674-L684】【11†L693-L702】。WS模式对权重复用友好（适用于大权重矩阵反复使用的场景），OS模式则将累加结果驻留在PE中直到输出完成，适合小批次或动态生成阶段，能减少中间写回【11†L674-L684】【11†L693-L702】。对于我们单头注意力（256×64），权重（Q/K/V矩阵）每行只使用一次，输出驻留可能更高效，可避免频繁的局部存储写回。  
- **阵列规模与向量化对比**：在小规模（S=256, D=64）情况下，可以使用高度展开的向量MAC单元或者小规模Systolic阵列。理论上，若流水线设计无气泡，可实现接近100%的MAC利用率。例如，某3D堆叠FlashAttention加速器在流水线满载时能做到每周期输出一个计算迭代，理论上接近100% MAC利用率【57†L314-L323】。相比之下，完全展开的向量MAC（如64路并行乘加）能提供极高并行度，但若前后级运算不同步、或需要依赖计算结果（如Softmax归一化）才可启动下一级，实际利用率可能下降。综合考虑，采用输出驻留的Systolic阵列并结合流水线（如如下第3点描述）可在保持高并行度的同时减少空闲周期【11†L693-L702】【57†L314-L323】。  

## 2. 存储层次与带宽隐藏  
- **多级SRAM与双缓冲**：SOTA设计通常将Q、K、V存于片上SRAM多银行，并采用“双缓冲”交替访问机制。例如，一个FPGA版FlashAttention实现中，通过乒乓（ping-pong）缓冲交替加载注意力块，在计算时并行预取下一块输入，从而避免了因存储访问而停顿【4†L47-L53】【13†L7-L10】。类似地，最新的3D-NPU设计在片上内存之间也采用了双缓冲机制以完全隐藏访问延迟【49†L468-L475】。结构上可以将Q、K、V拆分为若干独立银行：一组银行用于当前计算，另一组银行异步预取下一数据块。这样，当一个数据块在PE中计算时，下一数据块已经在后台加载，极大提高流水级并行度。  
- **带宽利用与并行读取**：为了并行计算Q*K<sup>T</sup>，通常需要同时读出Q的一行和K的一列。可以将Q按行分布在不同银行、K按列分布，或使用多端口SRAM实现并行读取，从硬件层面极大提高数据带宽利用。在在线Softmax场景下，板上SRAM资源充足，可充分布局多组缓冲区，使矩阵乘、归一化、V乘操作的读写互不冲突。  

## 3. 流水线调度与吞吐优化  
- **阶段并行化**：理想的Attention流水线将 **读SRAM → Q*K<sup>T</sup> → 在线Softmax更新 → P*V → 写SRAM** 这几阶段并行化。可设计为三级流水线：Stage 1负责QK点积与累加，Stage 2负责Softmax（求最大值、累积指数和归一化），Stage 3负责用Softmax结果乘V并累加输出。通过这样的流水线，在第一个输出周期之后，每个时钟周期都产生一个新的结果。例如，3D堆叠FlashAttention设计将这三个阶段映射到不同层并联执行，在流水线填充后实现了每周期完成一次注意力迭代的吞吐【57†L314-L323】【57†L378-L387】，大幅消除阶段间气泡。  
- **行级与块级重叠**：行级流水线是指对每一行Q的计算（QK、Softmax、PV）在时间上错开执行——当第i行的Softmax阶段进行时，可以并行开始第(i+1)行的QK阶段。块级流水线则将序列划分为若干行块，一块计算时预取下一块数据。如第2点所述的双缓冲即是块级并行化的一种。对于读写冲突，可使用在线Softmax算法：在处理每个QK元素时，持续更新行内最大值和累加指数和。这样，在最后一步计算Softmax和开始P*V之前，计算机已经部分有了Softmax输出的预测，可以逐步进行P*V操作，减少严格的读后写（RAW）依赖。总体上，按行流水线与按块流水线并用，可以在不引入FSM停顿的情况下，将Q*K、Softmax和PV操作高度交错执行。  
- **实证案例**：文献中诸如Fused FlashAttention 的GPU核将QK、Softmax、PV合并为一个流式核，可以边生成注意力分数边进行归一化和乘V，显著减少内存写回【47†L232-L241】【57†L378-L387】。该3D NPU工作也指出，通过流水化不同操作层并保持负载平衡，可实现连续输出且远高于传统2D阵列效率【57†L378-L387】【49†L468-L475】。

## 4. PPA约束与硬件资源复用  
- **乘法器共享**：在2M门限下，为了支持并行运算同时不超区，必须复用大型乘法器。比如可让原本并行执行QK<sup>T</sup>和P*V的乘加阵列共用硬件：先完成所有Q*K计算，再将相同的乘加单元用于P*V；或者采用时间分片方式轮流计算QK和PV（类似复用向量浮点指令）。这样，总乘法器数量不增加，但吞吐只减半。在Gate预算允许的情况下，一种折中是配置少量（如16-32路）并行乘法器，然后用流水线和双缓冲手段尽量消除空闲。  
- **加法器树优化**：注意力计算中大量累加操作可采用进位保存加法树（Carry-Save）方式减少运算深度。Wallace树或Dadda树是常用的多操作数加法结构：Wallace树最快但略多门，Dadda树稍省门数。针对Q8.8格式，可考虑舍弃最低若干比特以减小加法宽度（如仅保留高13~16位），从而减小加法器规模，但需评估对精度的影响。对于固定门限应用，还可使用流水线的前缀加法器（Kogge–Stone或Brent–Kung）平衡延迟和面积。一般而言，多级加法树通过流水线分割，既可减少级联延迟，又保证高吞吐。  
- **定点优化**：由于只需支持Q8.8，乘法结果为Q16.16。可设计定点专用乘法器和加法器，避免通用浮点硬件开销。EDA层面优化包括：利用布斯编码减少部分积数量、采用布尔逻辑门高效实现小位宽乘法（如完全展开的查找表），以及对累加路径使用局部截断或动态范围调整（如放弃过小的分量）。总之，通过复用硬件单元和定点专用电路，可在面积限制下尽量扩大并行度。  

## 5. 低成本非线性单元（Softmax）  
- **近似实现方法**：Softmax的核心是指数和除法运算。SOTA硬件常采用查找表（LUT）和分段线性（PLA）等近似。文献[30][32]提出，用双表（bipartite LUT）和一次加法即可近似exp，且用日志域差值通过小表实现除法【32†L233-L242】。该工作实现的全固定点Softmax仅用LUT加法单元，完全不用DSP，成本极低【32†L233-L242】。另一类方案是分段线性近似，例如将输入域（如[-10,0]）均匀划分，预存每段的斜率和截距【35†L500-L508】。每次Softmax指数运算只需一次乘加，硬件简单延迟低。  
- **方案对比**：LUT方法延迟最小：直接查表后加法输出，适合追求高吞吐；缺点是查找表存储需求较大，但可用bipartite技巧拆成两个小表【32†L343-L352】。PLA乘加则需要乘法器，延迟稍长但内存需求低；[35]中PLA方法在[-10,0]范围上，分段误差仅8.6%，硬件仅需一乘一加【35†L500-L508】。基于移位-加法的近似（如将e^x≈2^(x/c)形式，使用位移代替乘法【32†L262-L270】）可进一步减小乘法数目，但FPGA上动态移位器开销较大。总体上，LUT+加法结构通常面积最小、延迟最短：如[53]报道，FPGA上一个LUT硬件Softmax流水线仅占0.54% LUT和0.2% DSP【53†L60-L69】，可复制多个实例。分段线性和移位近似则在不同精度/资源条件下提供替代，实现较好的速度-面积平衡【35†L500-L508】【32†L262-L270】。  

**建议的RTL改进方案**：综合以上研究，可对现有架构作如下优化：采用输出驻留式阵列并尽量流水化QK、Softmax、PV阶段；在片内为Q/K/V设计多组双缓冲SRAM银行，实现边计算边加载；在硬件算子级面，引入三级流水线（计算QK、执行在线Softmax、累加P*V），并复用同一乘加阵列于不同阶段以节省面积；Softmax单元可选用LUT+加法结构以缩短路径，并利用查表或分段减小位宽；所有算术单元使用针对Q8.8的定制设计（如使用Wallace树或布斯乘法器，定点前缀加法器等）以降低门级开销。这样可在保持所需精度（MAE≤0.03）的同时，显著提升并行度和吞吐率，降低控制开销和周期数。上述优化思路均有文献支持【11†L674-L684】【32†L233-L242】【35†L500-L508】。
