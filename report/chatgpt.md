# 执行摘要

本报告深入调研了基于 FlashAttention 的注意力计算的算法演进、硬件实现和关键微结构设计，特别关注在资源极度受限的端侧 SoC (面积 ≤ 2M 门，片上缓存微小) 上如何实现高效的注意力运算。核心思路是利用**在线 Softmax**算法（Online Softmax）的可合并性质，在块级上增量计算注意力以避免存储完整的 $S\times S$ 矩阵。我们分析了 FlashAttention V1/V2/V3 的算法改进，以及近年来提出的硬件友好变体（如量化 Softmax、无除法 Softmax 等）。在硬件架构方面，调研了学术界和工业界针对注意力算子（FlashAttention 及其变种）的专用加速设计，包括基于脉冲阵列（systolic array）的**SystolicAttention (FSA)**、基于 Tile-Fabric 的**FlatAttention**、MIT 提出的**FuseMax**架构，以及 MIT/华为等提出的边缘注意力加速（如 SpAtten）设计。我们深度剖析了这些设计如何将 $Q,K,V$ 张量块映射到计算单元阵列，如何在矩阵乘法（$QK^T$、$P\cdot V$）和 Softmax 的“求最大值&求和”操作之间进行流水线重叠。针对极端低片上存储要求，总结了 K/V Tile 复用策略（如 Ping-Pong 缓冲、双缓冲）、SRAM 资源与外部带宽的权衡，以及如何利用寄存器维护每行的 **m** (行最大值)、**l** (行归一化累加) 和 **acc** (行输出累加) 状态。精度与运算单元方面，我们调研了硬件实现 Softmax 中指数和倒数的方法：如基于 LUT 的指数逼近、分段线性插值、泰勒展开、牛顿迭代等，并引用了相关专利和论文。最后，对各类架构的 PPA 指标（逻辑资源、SRAM 容量/面积、运行周期、主频、带宽利用、精度损失等）进行了整理对比，并给出了在**Q8.8 定点、面积SRAM极限**条件下的加速器设计建议，如尽量使用在线 Softmax 流水线、硬件近似计算、双缓冲并行等技术。  

# 1. 基础理论与算法演进

**FlashAttention** 的核心在于把注意力计算拆成块级（tiling）流式执行，从而避免 $S\times S$ 矩阵的完整生成。其基础是**在线Softmax**（Online Softmax）算法：对输入 $x_i$ 块迭代更新行最大值和累加项，可在一个循环内完成 Softmax 的计算。Milakov 等人的工作提出了一个在线归一化算法，其等价形式定义了一个二元操作：记每块的状态为 $(m,d)$，对应块内最大值和指数和，则有【43†L301-L310】  
$$
(m_i,d_i)\;\oplus\;(m_j,d_j)\;=\;\bigl(\max(m_i,m_j),\;d_i\exp(m_i-\max(m_i,m_j))+d_j\exp(m_j-\max(m_i,m_j))\bigr)\,,
$$  
这一操作可并行和交换【43†L316-L320】，允许分块计算后合并结果。FlashAttention V1 将该思想应用于 GPU，按 Q/K 小块计算 $S=QK^T$，边算边更新每行的最大值 $m$ 和归一化累加 $d$，并按需 **在线地** 归一化输出。FlashAttention V2 在此基础上重排计算次序（如【10†L50-L58】所述），进一步减少不必要的操作开销：例如只计算一次行归一化因子 $L=\log\sum\exp$ 而不分开保存 $m$ 和 $d$（如【10†L56-L58】所示）。最新的 FlashAttention-3 引入了混合精度、异步 warp 等 GPU 优化，但其核心思想仍依托在线 Softmax 的原理。

**软硬件友好Softmax变体：** 针对硬件实现，还提出了多种软max近似或整数化方案。例如，**SoftmAP** (SIJTU 2023) 利用二阶多项式逼近 $e^x$ 并用 Barrett 乘法避免除法【15†L436-L444】；**ConSmax** (2024 arXiv) 将 Softmax 的最大值搜索和求和操作转化为可并行的查表计算，通过分段小 LUT（将 8 位输入拆成 4+4 位）实现无损指数运算，并“同步自由”避免除法同步开销【25†L366-L374】【25†L377-L385】；**Softermax** (DAC’21) 则提出将 Softmax 基数换为 2（base-2 Softmax），使得归一化只需位移，而倒数计算用线性插值近似【61†L91-L99】。这些方法在硬件上大幅降低了复杂运算：如 ConSmax 实现面积仅 0.0008 mm² (@16nm)【25†L370-L378】；Softermax 的 Unnormed 单元面积仅为传统基线的 0.25×，能耗为 0.10×【63†L452-L456】，整个 PE 设计面积 0.90×，能耗 0.43×【63†L452-L456】，结合其软硬件协同微调，确保了精度几乎无损（<0.5%）【63†L452-L456】【63†L484-L489】。

# 2. 硬件架构与数据流设计

## 2.1 主流硬件架构

- **SystolicAttention (FSA)**【31†L188-L193】【31†L197-L201】：该架构在传统的二维脉冲阵列上全面执行 FlashAttention。其 RTL 实现仅比原始阵列增加 12% 面积【31†L188-L193】，16nm 下可达 1.5GHz 频率（FPGA 下为 70MHz）。关键在于：所有的点操作（如 `exp`、行最大/求和）均通过阵列自身资源完成，无需额外向量单元。行最大与求和被重塑为阵列内的并行归约操作，滚动计算并叠加；`exp(x)` 利用线性插值方法近似（因输入总 ≤0，可以分为整数与分数部分，用插值重用乘法单元）【31†L169-L174】。通过精心调度（SystolicAttention 调度算法），算法中的矩阵乘和 Softmax 操作可以在不同阶段交错进行，从而在同一次计算迭代中重叠多种运算【31†L174-L183】。最终效果为 FLOPs 利用率大幅提升（对比 AWS NeuronCore-v2 和 TPUv5e 分别提高 1.77× 和 4.83×【31†L197-L201】）。FSA 架构为面向工业级的 Attention ASIC 提供了关键思路。

- **FlatAttention**【21†L54-L63】：针对多 Tile 并行体系结构（如大量小 PE 组成的网格）提出。其利用片上网络原语（如广播/归约）实现多头注意力的跨 Tile 数据交换，通过“顺序扁平化”数据流显著降低外部访问。FlatAttention 实现中报告其硬件利用率高达 89.3%，相较于直接在同类硬件上执行 FlashAttention-3 数据流，性能提升约 4.1×，外部带宽需求减少 16×【21†L54-L63】。

- **FuseMax** (MIT, MICRO’24)**【28†L1-L4】：利用“扩展张量算子”概念，将 FlashAttention-2 的一遍算子映射到空间架构。FuseMax 突出特点是任意序列长度下片上缓存量不变、几乎 100% 计算单元利用率（2D 和 1D 部分均高效使用）。与之前的类 FLAT 架构相比，它在注意力层上平均 6.7× 加速，能源却仅 79%【28†L1-L4】，整段 Transformer 推理加速 5.3×，能耗 83%【28†L1-L4】。

- **SpAtten** (HPCA’21)**【23†L35-L43】：算法-硬件协同设计，通过**级联 Token/Head 剪枝**和**渐进量化**大幅削减 Attention 计算。SpAtten 在硬件上设计了高吞吐 Top-$k$ 单元，并采用多级缓存策略。实验表明，平均可减少 10× DRAM 访问（无精度损失），实现对比现有加速器（A³、MNNFast、GPU、CPU）约 1.6×, 3×, 162×, 347× 的速度提升，以及巨大的能耗降低【23†L35-L43】。其思想对于边缘场景（因序列长度小，对简单加速器友好）具有借鉴意义。

## 2.2 数据流映射与流水线

在上述架构中，Attention 的计算被拆解为三个部分：**矩阵乘**$S = Q K^T$、**软max归一化**$P = \operatorname{softmax}(S)$、以及**加权输出乘积**$O = P V$。其常见的数据流示例如下：

- **块化流水线**：将 $Q$ 按行或列划分成小块（tile），$K,V$ 同样划分。以块形式加载到片上后串行/并行计算。例如 FSA 中，设 Q 被分为多行块，K 划分多列块：对于每个 $Q_i$-块和每个 $K_j$-块，阵列不断输出对应的子矩阵乘积 $S_{ij}=Q_iK_j^T$。在矩阵乘过程中即可“边算边归约”：对每行累积更新当前最大值 $m_i$ 和指数和 $l_i$，见在线 Softmax 算法【43†L301-L310】。当处理下一个 $K$ 块时，必要时对之前累积结果进行缩放。如此循环直至完成当前 $Q_i$ 的所有 $K_j$，最后可在片内输出 $P_i = \exp(S_i - m_i)/l_i$ 再乘以对应 $V$ 块（累加到 $O_i$）以获得最终输出。

- **并行归约和复用**：在阵列或向量单元上，一般会为每一行保留寄存器来维护其 $m_i, l_i, acc_i$。例如上文 FPGA 实现【55†L115-L123】【55†L202-L207】和 SystolicAttention 都使用行级流水线：每个 PE（或寄存器组）负责自己行的更新。为了极小化缓存带宽，往往采用双缓冲机制：交替在两块小 SRAM/BRAM 中读取下一个 $K/V$ 块同时计算当前块，典型如“Ping-Pong Buffer”结构【56†L48-L53】【55†L115-L123】。这样可以实现内外存访存与计算的重叠，极大降低等待。另一方面，为了减小 SRAM 占用，以上设计均不存储完整 $S$，而是在流式过程中逐行输出累计结果（FlashAttention 算法就只保存一行的归一化因子，而不保留全 $S$ 矩阵【48†L322-L330】）。

- **矩阵乘与标量操作重叠**：在硬件实现中，矩阵乘（MAC）和 Softmax 运算往往可以局部交错执行。比如 FSA 将乘累与计算 $\exp$、比较、归约等操作细粒度交织（甚至利用乘法单元来做 $e^x$ 近似插值），使得多个操作**无须等待**之前阶段完成即可并行。在空间架构中，矩阵乘多用二维阵列，Softmax 的 “行最大值” 与 “行求和” 则可作为线性归约在阵列的通信网络中同步进行【31†L174-L183】。类似地，FlatAttention 等多 Tile 设计也会采用收敛网络（集合通信）来并行完成行级比较和累加。

# 3. 存储层级与缓存管理

由于端侧 SoC 片上存储极度受限，这些设计提出了多种内存层级策略以平衡 SRAM 用量与带宽需求：

- **块缓冲复用**：通常将 $K,V$ 张量块缓存于片上 SRAM/BRAM，供多个 $Q$ 块循环复用。例如 FPGA 实现采用交替读写的**Ping-Pong BRAM**，在处理一个 $K$ 块时同时预取下一个【56†L48-L53】【55†L115-L123】。这样一来，当当前块计算完成后即可立即开始下一个块，而无需空闲等待。多数设计还对 $Q$ 块作双缓冲：在处理当前 $Q_i$ 时，后台加载 $Q_{i+1}$。通过多级双缓冲和流水线，能够隐藏读写延迟，提高带宽利用率。

- **寄存器流水线状态**：FlashAttention 类算法会为每一行维护三个关键状态：行最大值 $m$、累加指数和 $l$、输出累加 $acc$。在硬件上，一般用寄存器阵列来保存它们。每处理一个新的 $K$ 块时，这三个状态会被更新：若出现新的更大值，则需对已有 $l$ 和 $acc$ 做指数缩放【48†L318-L326】；然后加入新块计算出的 $\exp(S-m)$ 贡献。寄存器更新只需少量逻辑（简单比较、乘法、加法），避免了更大的 SR[AM] 或外部访问。使用寄存器可实现精细化流水：每个输出行独立串行更新，无需跨行通信。

- **SRAM容量 vs 带宽权衡**：Tile 大小的选择是典型权衡：更大的块意味着更少轮次 (减少HBM访存)，但需要更多片上 SRAM 来缓存；更小块则对 SRAM 要求低，但增加总的内存访问量。FlatAttention 研究表明，合理增大块大小能线性减少内存访问【48†L360-L368】。在面积受限设计中，可选用较小块配合 aggressive 的带宽管理或采用高效压缩（如后向量化、量化）来应对。SpAtten 中的级联剪枝和渐进量化亦是从算法层面减少需要缓存的有效 $K,V$ 数量，从而节省带宽和存储。

- **寄存器和流水线结构**：例如，华硕等 FPGA 设计中为异步流水线而使用双存储区（Ping-Pong BRAM）来避免**批次间**的数据冲突【55†L202-L207】；SpAtten 设计了流水级 Top-$k$ 搜索引擎，保持每层的剩余 token 索引等状态。总体来看，低存储硬件设计中普遍原则是“多用寄存器、少用全局 SRAM，尽量串行流水化”。外部带宽则通过流水线读写和定点/稀疏技巧加以缓解。

# 4. 精度与专用运算单元设计

本设计严格要求输入输出为**16位带符号定点 (Q8.8)**，内部累加至少 32 位。实现 Softmax 的指数与除法是关键难点，常见硬件方案包括：

- **查找表与分段线性插值**：最直接的方法是基于查找表 (LUT) 实现 $e^x$。例如微软专利（CN117897688A）描述了一个基于底数 2 的指数单元：先用常数移位+加法将输入缩放至 $\log_2(e)$ 度量体系，分离整数与小数部分；然后对小数部分查表得到 $2^r$，将整数部分通过移位作用到结果指数上【41†L119-L123】。类似地，某些研究将指数函数分段 (piecewise linear)，把区间映射到简单算术操作【35†L1-L9】。我们可利用少量片内存存储关键点查表，如将 Q8.8 的输入拆分为高低位索引多个小表（参考 ConSmax 的 4+4 位 LUT【25†L370-L378】），或采用几段线性斜率逼近【35†L1-L9】【41†L119-L123】。这样可显著降低实现开销：ConSmax 8 位指数仅用两个 16-entry LUT，无需复杂乘法即可实现无损 $2^x$【25†L370-L378】。

- **牛顿迭代与多项式逼近**：指数和倒数都可用多项式或泰勒级数近似。例如 SoftmAP 算法用二次多项式逼近指数，结合 Barrett 乘法以移除除法运算【15†L436-L444】。对于倒数 (即 Softmax 的归一化因子 $1/\sum$)，常见方法是牛顿-拉弗森迭代：先用查表得到近似值，再迭代提升精度，最终用移位相加完成归一。Softermax 在此方向上创新：将 Softmax 基数换为 2，则所有归一化都化为对 2 的幂次移位；仅需针对分母的整数指数执行一次移位【61†L91-L99】；而对矩阵值点积的和做线性插值近似（见【61†L91-L99】），从而抛弃硬件乘法器等复杂部件。

- **寄存器位宽与累加**：由于 Q8.8 的乘加会产生最多 Q16.16 累加结果，实际设计中常使用 32 位累加寄存器来避免溢出。这样既保证中间动态范围，又能利用硬件对齐优化。一些方案（如 Softermax）甚至把部分运算放在更高精度（如 Q10.6、Q26.5）中以提高稳定性【64†L12-L20】。总之，在保证最终输出 16 位精度的前提下，可通过混合精度、饱和算术和尾数截断等手段进一步节省面积。

# 6. 面向 Q8.8 定点、资源受限加速器的设计建议

基于上述分析，为严格限片上资源的 Q8.8 定点 Attention IP 设计，可考虑以下策略：

1. **保持在线 Softmax 流水线**：继续沿用 FlashAttention 的**在线归一化**思路，在每个输出行上只保留 $m,l,acc$，边生成 $S_{ij}$ 边更新行状态，而不存储完整 $S$ 矩阵。这能将带宽需求降至线性，并使计算只需额外的常数寄存器。通过硬件流水将 $QK^T$ 计算、Softmax 归一化和 $P\cdot V$ 乘法紧密交错执行，无空闲周期。

2. **小片上缓存 + 双缓冲**：由于 SRAM 极其有限，尽量使用**足够小的块大小**（例如适配几百个元素）使之适合片上。采用**双缓冲/多级缓冲**技术：在计算一个 $K/V$ 块的同时预取下一个块；处理一个 $Q$ 块的同时准备下一个 $Q$。通过这种重叠，可以充分利用数据传输带宽。在具体实现上，可用两组小块 SRAM 交替读写（Ping-Pong），在一个缓冲区计算时另一缓冲区加载数据。

3. **近似/查表计算非线性**：禁止使用完整除法或指数运算单元，改用低成本硬件近似。常见方案：
   - **分段插值或LUT**：将指数输入映射到多个区间（可结合查表）以实现 $e^{x}$。例如将输入分为整数与小数部分，整数部分通过位移实现（参考【41†L119-L123】），小数部分通过小 LUT 查值。位宽 Q8.8 可拆分成高4位索引一个小表、低4位索引另一个表，如 ConSmax 所示【25†L370-L378】。
   - **Newton 或 Taylor 迭代**：对于 $1/x$ 或 $\sqrt{x}$，可以先查表得到初值，然后迭代。对于倒数，可采用牛顿迭代快速收敛。
   - **替代底数**：可以采用 Softermax 的思路，用底数 2 代替 $e$，这样归一化仅需位移，无需乘除【61†L91-L99】；对小数乘积部分做线性逼近。

4. **定点保持精度**：所有累加器至少用 32 位避免溢出。可对累加结果及时缩放或饱和，避免动态范围超限。必要时进行仿真校准位宽。激活函数（如 \(\exp\)）与归一化后结果需重新截断到 Q8.8 输出，同时保证不损失网络精度（可借助轻量微调）。

5. **流水线和并行度平衡**：在资源受限情况下，需权衡并行度与面积。可采用输出驻留（Output-Stationary）数据流：保持部分结果驻留在 PE 中不断累加输出【55†L197-L205】。此外，可考虑**空间复用**：例如多个 PE 共享一个指令流，通过时分复用或状态切换执行 Softmax 的不同阶段，以减少寄存器开销（注意这样会增加上下文切换寄存器状态量）。

6. **利用稀疏或剪枝**：如果场景允许，可将 SpAtten 的思想引入。例如级联剪枝不重要的 token 或 head，或对 $V$ 做近似低秩分解，从算法层面削减计算和内存需求。但需权衡准确率。

7. **查找表/自适应逻辑**：在片上实现小型固定查找表可有效加速 $\exp$ 和归一。可为典型操作设计专用硬件微架构（如 ConSmax 的分裂 LUT 结构【25†L370-L378】或 Softermax 的硬件管线【61†L91-L99】），以位掩码和移位替代复杂操作。通过设计同步计算路径，可进一步并行 Softmax 各步。

综上所述，面向面积和 SRAM 极限的定点 Attention IP，应采用**流式块执行+硬件近似计算**，最大限度剥离昂贵运算。通过小尺寸块划分、流水线双缓冲和查表近似方法，可在有限资源内实现和 FlashAttention 算法相当的精度和吞吐。以上策略结合表~PPA对比，可以为设计人员提供具体的参考依据和实现方向。
