## 5.1 2.1(1) 算法定义（SDPA 计算目标）

题目要求实现：

$$
O = softmax\left(\frac{QK^\top}{\sqrt{d}} + M\right)V
$$

### 当前判断

**满足。**

### 依据

- 当前 `fa_attention_core` 已在 baseline 参数下完成完整 `Q/K/V -> O` 端到端流程；
- `make test MODULE=fa_attention_core_full` 通过；
- `rtl-latency-profile` 给出相对 FP32 的误差：
  - `MAE = 0.000971925`
  - `MAX_AE = 0.00203197`

说明当前实现已在题目容许近似误差口径下完成目标计算。

## 5.2 2.1(2) FlashAttention-style 计算约束

题目要求：

1. 禁止显式存储注意力矩阵；
2. 必须使用 online softmax；
3. 必须分块处理 K/V。

### 当前判断

**满足。**

### 依据

- 当前主线未保存完整 `S×S` score/probability 矩阵；
- 当前主线维护 `m/l/acc` 行级上下文，属于 online softmax；
- 当前主线采用 `TQ=32`, `TK=64` 的 tile 数据流。

## 5.4 2.1(4) 数据格式（定点）

题目要求：

- 输入 `Q/K/V`：Q8.8
- 输出 `O`：Q8.8
- dot-product 累加至少 32-bit
- softmax 路径允许更高位宽

### 当前判断

**满足。**

### 依据

- 输入/输出路径均以 16-bit Q8.8 组织；
- 中间点积与累计使用 32-bit / 40-bit / 64-bit 混合中间位宽；
- softmax 路径中 `l/acc/recip` 等均采用更高位宽。

## 5.7 2.1(7) 存储与资源约束

题目强调：

- 禁止存储完整 `score/p` 矩阵；
- 允许缓存小块 K/V tile；
- 允许维护每行 `m/l/acc`；
- 若缓存全量 K/V，要量化带宽收益与 SRAM 代价。

### 当前判断

**部分满足，且存在面积风险。**

### 解释

#### 满足的部分

- 没有显式存储 `S×S` 矩阵；
- 使用 tile buffer 与行级上下文，符合 FlashAttention-style 初衷。

#### 风险的部分

- 当前 `fa_attention_core` 中的 tile buffer / 上下文存储总量不小；
- 若这些结构主要以寄存器阵列实现，则 top 级面积可能偏大；
- 本轮未完成 top 级正式面积闭环，因此对“资源约束完全满足”不能下最终结论。

因此本条的最准确口径是：

- **存储策略方向符合题意；**
- **面积口径下仍有明显待确认风险。**

## 5.13 2.2(4) 带宽目标

题目要求给出 `RD_BYTES/WR_BYTES` 统计与优化分析。

### 当前判断

**基本满足，但仍建议后续继续强化带宽分析。**

### 当前统计

- `RD_Q = 32,768 bytes`
- `RD_K = 262,144 bytes`
- `RD_V = 262,144 bytes`
- `WR_O = 32,768 bytes`
- `Total = 589,824 bytes`

### 当前解读

- 当前设计通过 tile 复用避免了 `S×S` 中间矩阵带宽灾难；
- 但 K/V 需要对每个 Q tile 重读，因此总外存 traffic 仍由 K/V 主导；
- 后续若能引入更强的片上 K/V 存储层级或 SRAM 宏化，将有望继续改善带宽与能效，但必须同时评估面积代价。
