# 01 项目摘要与阶段结论

## 1.1 报告目的

本报告面向当前主线 `rtl/`，回答以下四个核心问题：

1. 当前版本完成一次 baseline SDPA 需要多少周期；
2. 当前各模块在 500MHz 目标下是否满足要求；
3. 当前版本相对 `problem.md` 的符合性如何；
4. 下一步还需要在哪些方向继续调研与优化。

## 1.2 当前主线版本的结论摘要

### 周期指标

- 在修复 `fa_attention_core` 归一化主路径、真正接入 `fa_recip_nr_q16_16` 后，`make rtl-latency-profile` 生成的当前主线 RTL 结果为：
  - `total_cycles = 148656`
  - `profiled_total_cycles = 148656`
  - `profile_unaccounted_cycles = 0`
- 独立的 `make test MODULE=fa_attention_core_full` 端到端 cocotb 运行中，日志观察到：
  - `Core done after 148682 cycles`

二者只相差 **26 cycles**，量级约为 **0.017%**。本报告将 **148,656 cycles** 作为主结论，因为该数值来自当前专用 C++ profiler 输出的汇总 CSV；同时保留 cocotb 观测值作为独立交叉验证证据。

同时，本轮确认此前 `145,584 cycles` 与 0305 报告完全一致的根因并不是评估流错误，而是旧主线 `fa_attention_core` 在 `S_NORMALIZE` 中仍使用**内联除法**，并没有真正实例化 `fa_recip_nr_q16_16`。修复后，周期上涨到 `148,656`，增量为 **3,072 cycles**，这是 reciprocal 10 级流水在每行归一化启动时引入的真实主路径代价。

### 正确性指标

- Verilator C++ profiler 给出的当前 RTL 相对 FP32：
  - `MAE = 0.00291701`
  - `MAX_AE = 0.00588431`
- 题目门限为：
  - `mean_abs_error <= 0.03`
  - `max_abs_error <= 0.10`

因此当前主线 RTL 的误差**显著优于题目门限**。

### 模块级 500MHz 指标

本轮对当前主线 RTL 做了模块级 500MHz 复跑。结论如下：

| 模块 | 500MHz 结果 | 近似 Fmax | 说明 |
|---|---:|---:|---|
| `fa_mul_sat_q8_8` | 失败 | 432 MHz | 点状乘法/舍入/饱和链偏长 |
| `fa_exp_pwl_8seg_q1_15` | 失败 | 399 MHz | PWL 组合路径仍偏长 |
| `fa_recip_nr_q16_16` | 通过 | 501 MHz | 已在边界附近闭合 |
| `fa_axi_lite_regs` | 通过 | 787 MHz | 控制面满足 |

已确认不在主线数据通路中的模块：`fa_clip_signed`、`fa_online_softmax_update`、`fa_row_reduction_core`、`fa_core_controller`，以及同样未接入主线的 `fa_tile_buffer`、`fa_dot_product_d`，现已迁入 [useless/rtl_unused/README.md](useless/rtl_unused/README.md) 暂存，不再视为当前主线 `rtl/` 组成部分。

### 面积与 top 级结论

- 当前可确认的是：**模块级面积没有失控**；
- 但按题目“**含存储折算**”口径，若顶层缓存/上下文存储仍以寄存器阵列为主，则 top 级面积存在明显风险；
- 本轮**没有完成** top 级正式 STA 与正式面积口径闭环，因此不能宣称：
  - top 级满足 500MHz；
  - top 级满足 2M 等效门约束。

## 1.3 本轮相对于既有成果的新增内容

与此前 0305/0306 的阶段文档相比，本轮新增的关键结论有：

1. 证明此前 `145,584 cycles` 未反映 reciprocal 主路径落地，并在修复后把当前主线 RTL 的完整 baseline 周期数定量落到 **148,656 cycles**；
2. 对当前主线模块重新复核了 500MHz，不再仅引用历史实验结果；
3. 明确给出：
   - 周期目标满足；
   - 模块级 500MHz 仅部分满足；
   - top 级时序/面积仍待正式闭环；
4. 清理了未接入主线的 RTL 模块，避免后续继续把旁支模块结论误投影到 top/core 主路径；
5. 补充了一份可直接交给 deep-research agent 的问题拆解与调研输入清单。

## 1.4 本轮未进一步修改 RTL 的原因

本轮没有继续在主线 RTL 上做大改，不是因为找不到热点，而是因为当前未闭合问题已从“局部逻辑微调”升级为“**需要新微架构方案**”。

具体而言：

- `fa_mul_sat_q8_8` 与 `fa_exp_pwl_8seg_q1_15` 的违例属于**点状、局部**问题；
- 但 `fa_online_softmax_update` 的约 190MHz 结果说明：
  - 当前瓶颈是一个**跨 `m/l/acc` 递推的长反馈链**；
  - 若没有新的流水组织、交错多上下文、状态拆分或算法等价改写，继续在主线上做小修小补，无法把 190MHz 级别问题拉到 500MHz；
- 在缺少外部方案证据的情况下贸然重写，会显著提高：
  - 破坏当前功能正确性的风险；
  - 破坏已满足的周期指标与验证闭环的风险。

因此，本轮策略是：**先把现状报告完整、证据闭环，再把下一步调研任务拆清楚。**
