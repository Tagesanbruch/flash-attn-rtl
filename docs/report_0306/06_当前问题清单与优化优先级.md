# 06 当前问题清单与优化优先级

## 6.1 问题分层

当前问题并不是一个单点，而是可分成三层：

1. **架构级问题**：决定能否从约 190MHz 跳到更高频率；
2. **微结构级问题**：决定能否把局部点状算子推过 500MHz；
3. **实现级问题**：决定 top 级面积、P&R 与最终工程落地质量。

## 6.2 P0：online softmax recurrence 架构瓶颈

### 现象

- `fa_online_softmax_update` 约 189.5MHz；
- `fa_row_reduction_core` 约 188.9MHz；
- 远低于 500MHz。

### 根因

当前 `m/l/acc` 更新链包含强 loop-carried dependence：

$$
l_i = l_{i-1}\cdot e^{m_{i-1}-m_i} + e^{x_i-m_i}
$$

$$
acc_i = acc_{i-1}\cdot e^{m_{i-1}-m_i} + e^{x_i-m_i}\cdot v_i
$$

这意味着：

- 当前 token 的 `l/acc` 依赖上一个 token 的 `l/acc`；
- 单纯插流水会引入状态相关 hazard；
- 这不是“在中间打一拍”就能自然解决的问题。

### 优先级

**最高优先级。**

如果该问题不解决：

- top 级 500MHz 基本无望；
- 即便修掉其他点状模块，主频仍会被锁在 200MHz 以下量级。

## 6.3 P1：`fa_mul_sat_q8_8` 与 `fa_exp_pwl_8seg_q1_15` 的点状违例

### 现象

- `fa_mul_sat_q8_8`：432MHz
- `fa_exp_pwl_8seg_q1_15`：399MHz

### 解读

这两项问题本身并不算极重，但它们有两层意义：

1. 单独看，它们各自没过 500MHz；
2. 组合到更大的 softmax/score 路径里时，会继续放大主路径压力。

### 优先级

**第二优先级。**

理由：

- 一旦找到新的 online softmax 组织方式，这两个点状模块大概率也需要一并重构或重流水；
- 因此它们应与 P0 协同研究，而不是完全割裂。

## 6.4 P1：top 级面积高风险

### 现象

- 当前仍缺 top 级正式面积报告；
- 但按现有存储结构，top 面积存在明显风险。

### 根因

- `fa_attention_core` 内部片上存储位数不小；
- 若未引入 SRAM 宏化/存储分级，寄存器阵列面积会偏高；
- 题目面积口径又明确要求“含存储折算”。

### 优先级

**高优先级。**

理由：

- 即使周期和功能达标，若面积超 2M 门，同样无法给出完整合规结论；
- 这部分与频率优化并不独立，往往需要联合权衡：
  - 更大 buffer 可降带宽、但增面积；
  - 更强 time-mux 可降面积、但可能增 cycles。

## 6.5 P2：top 级 STA / P&R 证据不足

### 现象

- 当前只有模块级 STA；
- 尚无 top 级正式时序收敛结论。

### 解读

这意味着当前报告必须谨慎：

- 模块级热点可以定位方向；
- 但不能直接替代 top 级真实结果。

### 优先级

**高优先级，但在新结构方案确定后再执行更合理。**

因为若当前结构本身就只到 189MHz，过早投入 top 级 STA/P&R，只会更清楚地证明“仍不行”，而不会带来方案突破。

## 6.6 P2：K/V 重复读取带来的带宽与能效问题

### 现象

一次 baseline attention 的主存 traffic 约为：

$$
589{,}824\ \text{bytes}
$$

其中 K/V 占大头。

### 解读

当前设计已经避免了 `S×S` 中间矩阵带宽，但仍保留：

- 对每个 Q tile 重复读取全量 K/V；
- 这对真实系统带宽、功耗、吞吐都不够友好。

### 优先级

**中高优先级。**

在 baseline 周期已过线后，这会成为后续冲击更好系统性能的重要方向。

## 6.7 P3：验证维度仍可继续加强

### 当前已完成

- full attention core end-to-end
- top reg / start / cycles
- 当前 profiler 误差校验

### 仍可强化

- 极限 AXI backpressure
- 更细粒度 causal corner case
- 更大随机种子覆盖
- 新结构改造后的对齐/流水一致性专项测试

### 优先级

**中优先级。**

不是当前方案突破点，但会是任何后续大改成功与否的必要护栏。

## 6.8 当前最合理的优化优先顺序

综合本轮结果，建议后续工作按以下顺序推进：

1. **P0：调研 online softmax recurrence 的新微架构方案**
2. **P1：联合调研 `mul/exp` 的可流水、可低面积实现**
3. **P1：评估 top 存储层级重构与 SRAM 宏化方案**
4. **P2：在新结构选型后，再做 top 级 STA / 物理实现闭环**
5. **P3：把新结构纳入更完整验证矩阵**

## 6.9 本章结论

当前版本最关键的不是“再抠几百个 cycles”，而是：

- 如何把 **架构上正确** 的 baseline 实现，继续推进成 **频率可收敛、面积可交卷** 的版本。

因此，下一阶段最重要的工作不是盲改 RTL，而是带着明确问题列表去系统调研：

- 文献；
- 专利；
- 开源工程；
- 可综合商用 IP 的常见实现套路。

这正是下一章要整理的内容。
