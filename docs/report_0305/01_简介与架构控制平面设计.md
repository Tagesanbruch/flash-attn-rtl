# 1 简介与赛题背景

## 1.1 项目背景
在当今的大语言模型（LLM）推理系统中，Transformer 架构中的核心瓶颈之一在于自注意力（Self-Attention）机制的计算。传统的 Attention 计算需要完整的 $N \times N$ 注意力矩阵生成与归一化，导致显存容量与内存带宽的双重瓶颈。Flash Attention 的提出从算法层面打通了块化（Tiling）的计算路径，使内存访问（SRAM 上的读写）得以最小化，从而提升加速器的实际吞吐（Throughput）。

本项目聚焦于面向 FPGA/ASIC 的硬件端 Flash Attention 加速器 IP 设计。本次赛事的终极目标，是基于 RTL（SystemVerilog）语言，开发一套极低延迟且保持高度数值稳定性的定点化 Attention Core。

## 1.2 赛题目标与当前核心进展
本赛题主要对设计提出以下维度的极高要求，也是我们架构设计的核心出发点：
1. **P0级别 - 极致延时压降（Latency Reduction）**：初始基线由于控制层过载、内部流水线气泡及缺乏有效的数据预取机制，周期数高达 $236,288$ cycles，赛题要求我们压低总周期数至 300K cycles 内的极致水平。我们在本阶段通过双状态机并行管理与硬件乒乓缓存彻底实现了掩盖内存时延，周期数压至 $145,584$ cycles。
2. **定点化精度与数值稳定性（Numerical Stability）**：在纯定点 Q8.8 数据流下，非线性算子（Exp、Softmax）在尾数部分会发生严重截断甚至分母下溢。我们在运算核内部置入了底层的守护逻辑（如 `l_new_safe = (l_new == 0) ? 1 : l_new`）。
3. **P1级别 - 近似扫描与带宽平衡（PPA & Bandwidth Optimization）**：由于数据加载带宽限制了部分情况下的算力，我们需要平衡算流速率和 I/O 速率，使得总线利用率最优。目前通过数学 CModel 建模成功探究了最佳 PWL 近似参数及其对于整体硬件效率的潜在提升区间（注：PWL动态参数化当前主要为数学扫描，即将合入纯RTL实现）。
4. **异常容错闭环（Error Resilience）**：硬件在实际场景中会碰到超时、污染数据等情况，需要有健全的错误汇报机制传递到顶层。

## 1.3 整体架构总览 (Overall Architecture)
为了满足上述高吞吐量与精度的要求，我们重新设计了 `fa_attention_core` 算子内核。整体架构划分为三个互连的解耦流水线域：
1. **DMA 与预取总线控制（Prefetch Dispatcher）**：通过独立的状态机负责根据外部 AXI-4 交互协议向内存读取 K/V 数据分块（Tile）。
2. **乒乓双缓冲域（Ping-Pong Dual Buffer Domain）**：以 `active_bank` 及 `pref_target_bank` 的逻辑状态作为核心握手标识，K Cache 与 V Cache 均采用真双端口 SRAM 实例打底并分成两组逻辑 Bank 进行接力存储。
3. **高频计算大核（Compute Datapath）**：包括点积累加引擎（Dot-Product Vector Engine）、在线归一化网络（Online Softmax Updater）以及最终加权求和算子组。

在下述小节与后续章节中，我们将分别从计算范式、RTL数据通路及具体的 FSM 状态机角度层层剖析这个加速引擎。

# 2 控制平面与乒乓缓存深度解析

不同于传统的单线程 FSM 会将访存与计算强制串行化，导致计算单元在等待 AXI 传输时产生大量气泡空窗期。我们的核心突破在于 **双核异构状态机协同（Dual-FSM Asynchronous Collaboration）**。我们在 `rtl/core/fa_attention_core.sv` 内部实例化了 `prefetch_state_t` 及 `comp_state_t`。

## 2.1 计算状态机 `comp_state_t` 机制结构
计算状态机主要驱动算法逻辑的步骤，包含四大关键阶段：
- **`C_IDLE`**：复位统计数值以及配置寄存器，等待外层指令。
- **`C_DP_RUN`**：负责从指定的 SRAM Bank（当前轮次的 `active_bank`）中弹出数据送入点积引擎，此时会消耗多个连续时钟周期完成长度为 C 的点积计算，产生原始的未缩放 Score。
- **`C_SCORE_DONE` / `C_SOFTMAX_PREP`**：在这两个单周期控制状态中，触发并等待归一化和非线性缩放完成。首先计算最大值减法防止指数爆炸，随后锁存 Softmax $\exp()$ 函数的标量值和累加项，启动 PWL 逻辑流水。
- **`C_UPDATE_O`**：基于新生成的在线状态追踪器 $m, l$ 分别进行 `o_res` 的在线加权校正，从而避免了需要一整个大矩阵 $P$ 或全局归一化的过程。

计算状态机在每一个完整 Tile 处理完毕后，都会产生 `comp_done_pulse` 标志，告知预取状态机同步，然后翻转 `active_bank` 信号（代码对应 `active_bank <= ~active_bank;`）。

## 2.2 预取状态机 `prefetch_state_t` 与访存隐藏
我们在 `fa_attention_core` 中完全抽离出了 I/O 请求的依赖：
```systemverilog
// 取自 RTL 的预取端状态机定义
typedef enum logic [2:0] {
    PF_IDLE,
    PF_CMD_K,      // 发射读取 K 块的 DMA 突发指令
    PF_DATA_K,     // 将进来的 AXI 数据流装载入 K 缓存的备用 bank
    PF_CMD_V,      // 发射读取 V 块的 DMA 突发指令
    PF_DATA_V,     // 装载 V 数据入备用 bank
    PF_WAIT        // 等待当前主计算状态机耗尽旧的 Bank 数据
} prefetch_state_t;
```

**设计哲学解析：**
1. **重叠原理（Overlap Principle）**：当主核 `comp_state_t` 正在疯狂嚼吃 K/V (Bank 0) 计算时，`prefetch_state_t` 早已发出指令通过 AXI 将远端 DRAM 数据搬运充填至 K/V (Bank 1)。
2. **时序与握手控制**：预取机制填充完成后进入 `PF_WAIT`。此状态下预取侧处于静默待机。只有当计算侧发出换页完成（`active_bank` 翻转）后，预取状态机才被激活并跳回 `PF_CMD_K` 继续取下一轮数据。
3. **真实收益分析**：这一改进直接砍去了高达近 $90,000$ 个纯粹由 AXI 传输握手、寻址等待引起的死区时间。实现了近乎完美的 `Compute Bound`。如果通道内突发带宽能持续跟上，其宏观表现上相当于访存变为 0 耗时。

## 2.3 缓冲仲裁器设计 (Buffer Arbiter)
为了使得读写指令不仅不阻断而且绝对不冲突，我们在核心 RTL `fa_attention_core.sv` 对 `k_buf0`, `k_buf1`, `v_buf0`, `v_buf1` 的外围包裹了硬连线的 MUX 路由阵列：

```systemverilog
// Bank 0 的写入总受控于预取器当前目标（必须为0时才可见外部指令）
assign k_buf0_we = (pref_target_bank == 1'b0) ? pf_k_we : 1'b0;
assign v_buf0_we = (pref_target_bank == 1'b0) ? pf_v_we : 1'b0;

// 计算核的数据源永远只从当前的 active_bank 抽取
assign k_rdata = (active_bank == 1'b0) ? k_buf0_rdata : k_buf1_rdata;
```
**为什么这么做？**
传统的带有自旋锁的 SRAM 控制器或仲裁器会导致极大的门级面积开销（Area Overhead）和关键延迟（Critical Path Delay）。通过纯状态判定（由于两个状态机被设计为永远不可能同时对同一Bank进行同类操作，即所谓 Safety Guarantee），不仅避免了跨时钟域、跨流水站的控制开销，而且将选择器的逻辑深度降至一层 Latch/MUX 的级别，保障了系统达成更高时钟主频的潜力。
