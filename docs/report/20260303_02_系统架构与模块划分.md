# 2 系统架构与模块划分

## 2.1 架构目标与分层思路

FlashAttention IP 在工程实现上可分为三层：

1. **控制层（Control Plane）**：负责配置、启动、状态上报与异常收敛；
2. **数据搬运层（Memory Plane）**：负责外存到片上的 tile 级搬运；
3. **计算层（Compute Plane）**：负责点积、online softmax 更新与输出累积。

当前工程已经具备控制层主骨架和计算层关键子模块，搬运层尚在实现阶段。

## 2.2 顶层模块职责拆分

### 2.2.1 顶层与控制模块

- `rtl/top/fa_attention_ip_top.sv`：顶层拼接入口，当前已接入控制器与寄存器模块；
- `rtl/core/fa_core_controller.sv`：控制状态机，负责 START/BUSY/DONE 生命周期；
- `rtl/bus/fa_axi_lite_regs.sv`：寄存器读写、字段保持与状态映射。

这三者组成“可启动、可观测、可收敛”的基础闭环。

### 2.2.2 算法/算子模块

- `rtl/common/fa_mul_sat_q8_8.sv`：Q8.8 定点乘法与饱和；
- `rtl/softmax/fa_exp_pwl_8seg_q1_15.sv`：指数近似（分段线性）；
- `rtl/softmax/fa_recip_nr_q16_16.sv`：倒数近似（牛顿迭代）；
- `rtl/softmax/fa_online_softmax_update.sv`：`m/l/acc` 在线更新；
- `rtl/core/fa_row_reduction_core.sv`：行级归一化输出。

这些模块提供了从“score/value 输入”到“行级输出”的核心数值路径。

### 2.2.3 待补模块（决定是否达标）

- DMA 读写通道（AXI Master AR/AW/W/R/B）；
- tile buffer（K/V 至少一块，必要时含 Q 分块）；
- tile-loop 调度器（控制 j 方向迭代）；
- 带宽统计模块（RD_BYTES/WR_BYTES）。

其中 tiling 调度与 DMA 读写是 Baseline 达标的必要条件。

## 2.3 数据流视角的执行路径

完整目标路径应为：

1. 主机配置寄存器：地址、stride、scale、causal；
2. 启动后 DMA 分块读取 Q/K/V；
3. 对每个 query 行执行多 tile 迭代：
   - 计算 tile 内 `QK^T`；
   - online 更新 `m/l/acc`；
4. 最终归一化得到 O 行并写回；
5. 更新 CYCLES、RD/WR 统计，置 DONE。

当前已实现路径是上述流程的“控制骨架 + 子路径算法验证版本”，尚未实现第2/3/4步的硬件数据搬运闭环。

## 2.4 为什么必须先做“控制正确”再做“吞吐优化”

当前采用的迭代策略是：

- 第一步：把状态与寄存器语义做对（避免后续 debug 时定位困难）；
- 第二步：把 online softmax 子路径做稳定（确保数值行为可控）；
- 第三步：接入 DMA 与 tiling 后，再做并行度与流水优化。

这种路径的收益是：每次新增复杂度时，都有上层可观测信号和下层 golden 对照，能快速定位问题。

## 2.5 架构边界与不做事项

为了保持 Baseline 聚焦，本阶段明确不做：

- 多 head 并行；
- 可变 S/d 通用化接口；
- stream 接口与任务队列；
- bonus 精度（BF16/FP16/FP8）路线。

这些内容可在 Baseline 通过后作为独立 bonus 工程推进。

## 2.6 本章小结

当前系统架构已经形成“可演进”的框架：控制面与算子面基础可用，接下来将以 DMA + tiling 把数据面补齐，实现真正的 FlashAttention 端到端执行链。
