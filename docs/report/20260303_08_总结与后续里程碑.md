# 8 总结与后续里程碑

## 8.1 阶段总结

本阶段的主要贡献是完成了 FlashAttention 工程的“基础可验证内核”：

- 在算法侧，online softmax 关键递推已在 RTL 层落地；
- 在控制侧，AXI-Lite 寄存器与状态流语义已跑通；
- 在验证侧，建立了 cocotb 与 Python 双链路；
- 在工程侧，建立了单模块综合/STA 可复现流程。

这些成果使项目从“概念方案”进入“可迭代工程”，为下一阶段系统闭环奠定基础。

## 8.2 当前阶段不足

现阶段不足同样明确：

1. 数据搬运与计算尚未形成完整硬件闭环；
2. Baseline 关键指标（cycles、带宽、top 级 PPA）尚无最终证据；
3. 端到端误差门限尚停留在模型级结论，未迁移到 RTL 实测。

因此当前版本不应被描述为“完成版”，而应定位为“中期版本”。

## 8.3 后续里程碑（建议用于周计划）

### 里程碑 M1：DMA 最小闭环

- 输出：能完成一次 Q/K/V 读 + O 写；
- 判定：无死锁、状态正确、数据可读回。

### 里程碑 M2：tiling + online 端到端

- 输出：`S=32/64` 缩尺端到端与 golden 对齐；
- 判定：跨 tile 状态一致，causal 行为正确。

### 里程碑 M3：S256D64 Baseline 正确性

- 输出：固定规模误差报告；
- 判定：满足 MAE/MaxAE 门限。

### 里程碑 M4：性能与带宽报告

- 输出：CYCLES、RD_BYTES、WR_BYTES；
- 判定：统计可重复，可用于优化对比。

### 里程碑 M5：top 级实现报告

- 输出：综合/时序/功耗（条件允许）；
- 判定：形成提交级完整报告。

## 8.4 对最终提交的建议

1. 报告中明确区分“已实测”和“规划项”，避免混淆；
2. 每个关键结论都给出对应脚本/文件位置；
3. 图表优先展示：误差、cycles、带宽、时序四类核心指标；
4. 在 Baseline 完成前，不并行开展 bonus，保证版本纯净。

## 8.5 本章结论

项目已经走在正确技术路径上。接下来最重要的是执行节奏：先把 DMA+tiling+端到端验证做实，再用指标数据完成性能与实现闭环，这样才能稳定满足赛题 Baseline 的完整交付要求。
