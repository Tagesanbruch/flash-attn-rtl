# 5 验证方案与阶段结果

## 5.1 验证目标分层

为降低复杂系统一次性联调风险，验证按三层推进：

1. **算子层**：单模块功能正确与边界行为；
2. **控制层**：寄存器语义、启动完成流程；
3. **系统层**：端到端数据一致性、误差门限、性能计数。

当前工程已完成第1与第2层，大部分第3层仍待 DMA+tiling 完成后落地。

## 5.2 已建立验证环境

### 5.2.1 cocotb 回归

核心测试位于 `dv/cocotb/tests/`，已经覆盖：

- 乘法饱和模块；
- exp 近似模块；
- 倒数近似模块；
- online softmax 更新模块；
- 顶层寄存器流程测试。

### 5.2.2 Python 参考与对比

- `dv/python/ref_attention.py`：参考实现；
- `dv/python/algorithm_audit.py`：严格 online 与 direct softmax 审计；
- `dv/python/torch_compare.py`：与 PyTorch 对比，输出多 seed 统计。

该链路用于确认算法路线没有偏离，并为 RTL 端到端验证提供 golden 数据。

## 5.3 本阶段关键验证结论

### 5.3.1 lint 与回归

- `make lint`：通过；
- `make regress`：通过（已实现模块集）；
- `make test MODULE=fa_attention_ip_top`：通过（寄存器流程与语义）。

### 5.3.2 算法严格一致性

`report/data/20260303_algorithm_audit.csv` 显示 online exact 与 direct softmax 最大偏差约 $4.77\times10^{-7}$。这说明在线递推公式实现在数值上正确。

### 5.3.3 与 torch 误差对比

在 `S=256,d=64,causal` 多 seed 统计下，当前模型侧结果约为：

- worst MAE = 0.000264
- worst MaxAE = 0.005044

相较赛题门限（MAE <= 0.03，MaxAE <= 0.10）有较大余量。该结论用于支撑“算法路径可行”，但不等同于“RTL 端到端已通过”。

## 5.4 当前未覆盖项（必须正视）

以下验证项在当前阶段尚未完成：

1. DMA 读写时序与 backpressure 场景；
2. tile 边界一致性（尤其跨 tile 的 `m/l/acc` 传播）；
3. RTL 端到端随机 Q/K/V 验证；
4. causal corner 的 RTL 波形级证据；
5. `CYCLES` 与 `RD/WR bytes` 的真实统计对照。

这些项正是 Baseline 评测会关注的硬指标，必须在下一阶段优先补齐。

## 5.5 下一阶段验证设计（建议）

### 5.5.1 用例分组

- Group A：DMA 通道正确性（地址、突发、错误）；
- Group B：tile-loop 正确性（边界、跨 tile 累积）；
- Group C：端到端正确性（误差门限）；
- Group D：性能统计（cycles/bytes）。

### 5.5.2 每组最低验收标准

- A 组：无握手死锁、数据一致、错误可上报；
- B 组：tile 切换前后与软件模型一致；
- C 组：满足 MAE/MaxAE 门限；
- D 组：输出可重复的统计结果与优化对比。

## 5.6 本章小结

当前验证体系已经把“单模块正确”和“控制语义正确”打牢。接下来工作重心应从“算子正确性”切换到“系统级可验证性”，即 DMA+tiling 端到端闭环。

## 5.7 2026-03-04 复核更新

- 新增一键复核命令：`make check-sdpa-verilator-cpp`（纯 C++ Verilator TB，直接驱动 RTL + 独立 C++ SDPA 对比）。
