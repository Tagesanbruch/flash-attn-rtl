# 4 RTL实现与接口寄存器

## 4.1 当前 RTL 组成与状态

当前 RTL 已形成“可运行骨架 + 核心算子子路径”：

- 顶层与控制：
  - `rtl/top/fa_attention_ip_top.sv`
  - `rtl/core/fa_core_controller.sv`
  - `rtl/bus/fa_axi_lite_regs.sv`
- 算子与 softmax：
  - `rtl/common/fa_mul_sat_q8_8.sv`
  - `rtl/softmax/fa_exp_pwl_8seg_q1_15.sv`
  - `rtl/softmax/fa_recip_nr_q16_16.sv`
  - `rtl/softmax/fa_online_softmax_update.sv`
  - `rtl/core/fa_row_reduction_core.sv`

工程状态上，控制路径和算子路径均能独立验证；缺失点在于 DMA 与 tile-loop 的系统拼接。

## 4.2 控制器状态机（fa_core_controller）

当前控制器承担最小生命周期管理：

1. 等待 `CTRL.START`；
2. 置 `STATUS.BUSY` 并计数；
3. 达到完成条件后置 `STATUS.DONE`；
4. 等待软件清除 DONE 或进入下一次启动。

虽然当前完成条件仍是骨架逻辑，但该状态机已经提供后续接入 DMA/TILE 各阶段握手的锚点。后续可将“完成条件”替换为真实事件：

- 所有 Q 行处理结束；
- 最后一个 O burst `B` 响应返回；
- 错误标志未置位。

## 4.3 寄存器设计与语义

寄存器实现文件：`rtl/bus/fa_axi_lite_regs.sv`。

### 4.3.1 已实现的关键字段

- `CTRL`：`START/SOFT_RESET/IRQ_EN`
- `STATUS`：`BUSY/DONE/ERROR`
- `CFG`：`CAUSAL_EN`
- `Q/K/V/O_BASE_{L,H}`：地址配置
- `STRIDE_BYTES`：行跨度
- `NEG_LARGE`：mask 负大值
- `SCALE`：$1/\sqrt{d}$ 缩放常量
- `CYCLES`：执行周期读回

### 4.3.2 已验证的语义

通过 cocotb 已验证：

- 默认值正确；
- R/W 字段可读回；
- DONE 可写 1 清除（W1C）；
- CYCLES 为只读；
- START 可以触发 BUSY->DONE 状态变化。

这些语义与赛题要求一致，为后续 DMA 接入后“软件驱动不变”提供保障。

## 4.4 算子模块实现要点

### 4.4.1 定点乘法与饱和

`fa_mul_sat_q8_8` 的目标是保证 Q8.8 乘法在边界条件下可控：

- 保留中间高位避免早截断；
- 输出前统一舍入/截断策略；
- 极值时执行有符号饱和。

### 4.4.2 exp 与 recip 近似

- `fa_exp_pwl_8seg_q1_15`：分段线性近似，追求低面积与中等精度平衡；
- `fa_recip_nr_q16_16`：通过 NR 迭代提高倒数精度，适合 softmax 归一化尾段。

这两类近似在综合后对时序和面积影响明显，后续 top 级优化重点通常会落在它们周边的流水级切分。

### 4.4.3 online 更新与行归约

- `fa_online_softmax_update`：执行 `m/l/acc` 递推；
- `fa_row_reduction_core`：计算最终输出向量分量。

两者共同构成“无全矩阵存储”的核心计算链。

## 4.5 待实现 RTL（决定 Baseline 是否闭环）

### 4.5.1 DMA 主接口

当前 top 未导出完整 `m_axi_*` 通道。需补齐：

- 读：`AR/R` 用于读取 Q/K/V；
- 写：`AW/W/B` 用于写回 O；
- 错误处理：将 `RRESP/BRESP` 异常映射到 `STATUS.ERROR`。

### 4.5.2 tile 缓冲与调度

必须新增：

- K/V tile buffer；
- tile-loop FSM；
- 跨 tile 的 `m/l/acc` 保持寄存器；
- 行结束写回控制。

### 4.5.3 性能计数器

为满足赛题统计项，需在控制路径加：

- `RD_BYTES`
- `WR_BYTES`
- （可选）`STALL_CYCLES` 与 `COMP_CYCLES`，便于性能剖析。

## 4.6 本章小结

当前 RTL 已完成“可验证骨架 + 算法关键块”，能支撑后续快速扩展。下一阶段的核心是让 DMA、tile 调度与现有算子链无缝拼接，形成真正端到端 attention 硬件流程。
