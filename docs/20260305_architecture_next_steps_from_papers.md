# 20260305 基于论文与TeX源码的下一步架构实施建议（面向当前RTL）

## 1. 结论先行

基于已读三份调研报告、关键论文 TeX 源码与当前项目状态，建议采用如下主策略：

1. **Baseline 继续坚持“FlashAttention在线 softmax + tile 流式 + 不存 SxS”主线，不引入复杂 NoC。**
2. **短期性能主攻“控制开销压缩 + 跨阶段重叠”，而不是再加大算力并行度。**
3. **数值路径主攻“稳定在线归一化 + 受控近似 exp/recip + 更高精度累加”，优先保障误差门限。**
4. **Bonus 以“可渐进复用”的顺序推进：S 扩展/多head → 精度拓展（BF16/FP16 或 INT8/FP8 思路）→ 队列化 DMA。**

这一路线与当前 RTL 已达到 `<300k cycles` 的事实兼容（已有约 236k），目标是进一步拉开余量并降低实现风险。

---

## 2. 当前实现状态与瓶颈（和论文观点对齐）

根据现有文档：

- 当前 RTL 已 row2 并行，`total_cycles` 约 236,288，满足 baseline 周期目标。
- 主要差距来自 **compute 控制/调度开销**，而不是 normalize 吞吐。
- 误差分解显示主矛盾在 **acc 路径精度与稳定性**，并非 dot 本身。

这与 FlashAttention 系列核心观点一致：

- FA1/FA2：性能瓶颈常来自非 matmul 与数据搬运/控制，而不仅是乘加峰值。
- FA3：进一步指出应尽量把“非乘加工作”隐藏在可重叠时隙中。

对当前竞赛 RTL 的直接含义是：

- 下一阶段不宜优先扩大 `DP_LANES`；
- 应优先减少 `C_*` 子状态切换和空泡，并让 `load/compute/normalize/writeback` 形成稳定流水重叠。

## 3. 论文到可执行动作的映射

### 3.1 FlashAttention / FlashAttention-2 / FlashAttention-3

**提炼点（对硬件实现最有价值）：**

1. 在线 softmax 的状态最小化（`m` + `l` 或 `lse`）是正确方向；
2. 算法重排可降低非 matmul FLOPs 与中间读写；
3. 并行层次应先做“可独立块并行”，再做更激进的异步流水；
4. 软硬件协同目标是“把特殊函数/归一化开销藏到主循环重叠里”。

**对应到当前 RTL 的动作：**

- A1：保留现有在线 softmax 状态机，但把 `score_done -> softmax_pv -> next` 的边界合并，减少显式控制拍。
- A2：重构 `S_LOAD_K/S_LOAD_V/S_COMPUTE` 调度为“两级缓冲 + 前后拍重叠”。
- A3：把 `exp` 与 `pv` 局部流水成固定节拍模板，避免条件分支打断。
- A4：评估 `l,m` 与 `lse` 两种存储形态面积/延迟，选控制最简的一种（通常 `lse` 更省状态传递）。

### 3.2 SpAtten / Sanger / BitStopper / PADE（动态稀疏系）

**提炼点：**

1. 稀疏预测若与执行解耦，会引入额外访存与控制负担；
2. 细粒度剪枝有收益，但需要稳健阈值与异步调度，否则吞吐损失大；
3. 对 baseline 固定规模（S=256,d=64）而言，全量精确 FA 往往更稳，稀疏更适合作为 bonus 研究项。

**对应动作：**

- B1（baseline）：不引入运行时稀疏剪枝主路径，避免破坏确定性与验收稳定性。
- B2（bonus 研究）：新增“可关断”的轻量 token 过滤实验分支，仅做可对比实验，不污染 baseline 主线。
- B3：如果做稀疏，优先做“块级阈值 + 固定上限 top-k”而非完全动态 OOO，先保证可验证性。

### 3.3 MSAGA / SA（单阵列融合思想）

**提炼点：**

1. 将 `rowmax/sub/exp/rowsum/pv` 在数据驻留期间融合，可显著缩短 tile 周期；
2. 关键不是引入复杂互连，而是利用已有数据路径完成“就地操作与重叠”。

**对应动作：**

- C1：在当前 datapath 内增强“行级 reduction + broadcast”能力，减少中间寄存器往返。
- C2：softmax 子流水从“阶段式”改为“流经式”（边到达边更新局部统计）。
- C3：将 normalize 后移并批处理，减少对主计算环路的阻塞。

### 3.4 FPGA/FAMOUS 及其他实现型论文

**提炼点：**

1. 固定 tile + 运行时可配置参数可降低实现风险；
2. 明确数据布局与访存对齐，比复杂算法 trick 更容易形成稳定收益。

**对应动作：**

- D1：明确并固化 Q/K/V/O 的 DMA 突发粒度与对齐约束；
- D2：对 `STRIDE_BYTES`、`CAUSAL_EN`、基地址编程做压力回归；
- D3：把计数器/性能寄存器从“调试信息”升级为验收指标输出。

## 4. Baseline 下一步（必须做，按优先级）

### P0（本周，直接增益）

1. **控制路径压缩**
   - 合并 compute 子状态，减少 `cs_ctrl_cycles`。
   - 目标：`Compute+Norm` 再降 15% 左右。

2. **Load/Compute 轻量重叠（双缓冲）**
   - K/V tile 采用 ping-pong buffer。
   - 目标：减少主状态等待拍，进一步压低总周期。

3. **数值稳定性守护**
   - 固化 `m/l` 更新顺序与舍入策略；
   - 对 `NEG_LARGE` 与 mask 路径加一致性检查。

### P1（下周，稳态优化）

4. **exp/recip 近似模块 PPA 扫描**
   - PWL 段数（如 8 段）与误差/面积折中表；
   - 形成可复现配置而非单点实现。

5. **访存与带宽统计闭环**
   - 将 `RD_BYTES/WR_BYTES` 与周期同批输出；
   - 报告中明确“tile 复用带来的外存收益”。

6. **回归覆盖补齐**
   - causal corner case、随机种子、寄存器流程、异常路径（ERROR 位）。

### P2（可选强化）

7. **row 并行深度试探（row4 仅实验）**
   - 用 cmodel 先估计，再做 RTL 小范围原型；
   - 若控制开销反弹或时序风险上升，及时回退。

## 5. Bonus 路线图（建议顺序）

### Bonus-1：多 head（head=4/8）

- 以“head 外层并行 + 共享控制模板”为主；
- 重点是地址/stride 规划与 DMA 调度，不先做复杂互联。

### Bonus-2：更长序列（S=512）

- 保持不存 SxS 原则；
- 先增大 tile 循环层级，不盲目增大片上缓存。

### Bonus-3：精度扩展（BF16/FP16 或 INT8/FP8 思路）

- 借鉴 FA3 的“块量化 + 缩放因子”思想，但保持在线 softmax 主干不变；
- 以“误差门限 + 周期 + 面积”三维同时评估。

### Bonus-4：DMA/任务队列

- 增加链式任务描述符；
- 减少主机反复启动开销，提升端到端吞吐。

---

## 6. 建议暂缓或谨慎事项

1. **暂缓引入通用 NoC。** 当前规模下收益不确定，控制复杂度与验证成本高。
2. **暂缓把动态稀疏作为 baseline 主路径。** 容易引入不稳定误差与回归复杂度。
3. **谨慎增加并行度参数。** 在未解决控制瓶颈前，继续堆 lanes 往往边际收益很低。
