## 10. 逻辑综合与物理实现

### 10.1 具体方案

当前综合与时序分析采用两阶段策略。前期使用 Yosys 进行逻辑综合，并通过 iEDA 完成基于 icsprout55 的 pre-P\&R 静态时序分析，主要目标是定位中前端的结构瓶颈，而不是给出最终流片级物理结果。后期若项目进入更完整的实现阶段，则再迁移到 Cadence 工具链做完整后端流程，包括 floorplan、placement、CTS、routing、功耗分析和版图签核。

这种策略的合理性在于，当前项目仍处于架构快速迭代期。对于 QK、Online Softmax、Normalization 等模块，决定频率上限的往往是“这一拍做了什么组合逻辑”，而不是“标准单元摆在芯片上的具体位置”。因此先用综合和 STA 快速识别最长路径、面积量级和结构性趋势，再决定是否继续拆拍或重构 datapath，是成本最低、信息量最高的做法。

### 10.2 版图结果与面积分析

当前尚无完整 Cadence 版图结果，因此面积分析仍以综合报告中的 cell area 为主。尽管如此，这些数据已经足以揭示各热点模块的相对规模。举例而言，`fa_online_softmax_ctx/exp_d` 的面积约为 `27216.28`，说明 softmax leaf 本身虽然时序敏感，但绝对面积并不高；`fa_o_normalize_block_pipe/exp_d` 的面积约为 `238672.84`，说明 64bit 归一化链路会带来较大面积负担；QK 点积实验 `exp_g` 与 `exp_h` 的面积分别约为 `272855.24` 和 `286906.48`，则表明高宽度并行乘加树是当前最主要的面积热点之一。倒数模块 `fa_recip_nr_q16_16/exp_c` 的面积约为 `60594`，在达到 500MHz 收敛的同时面积增量仍然可接受。需要额外说明的是：当前主线把 `ctx` 以按维复制的方式接回 core，因此单实例 `27216.28` 只能作为 leaf 级数据参考，不能直接当作当前 softmax 子图总面积来理解。

这些数据有一个直接推论。若未来需要进一步压缩面积，单靠在线 softmax 或倒数模块的局部优化意义有限，因为它们的绝对面积并不构成系统主导项；真正需要做结构权衡的是 QK 和归一化等高位宽、高并行路径。与此同时，若只从“面积—频率收益比”角度看，Online Softmax 是目前最值得继续保留和吸收独立实验成果的模块，因为它已经证明可以以相对温和的面积代价换来非常显著的频率提升。

#### 10.3.2 面向 500MHz 的下一步实验方向（QK / Norm）

<!-- 图10-4：Norm 从 base 到 exp_d 的数据路径拆分图 -->

首先看 QK。`exp_f/g/h` 已经证明“乘法首拍 + 全流水二叉树”是正确方向，且 `exp_h` 把最差端点收缩到 `mult*_r`，说明当前瓶颈已从宽加法树转移到**输入总线驱动乘法器阵列**与**单乘法器叶级路径**。因此下一轮最值得做的实验，不应再回到 `exp_e` 那类局部乘加块细修，而应围绕以下三类：

1. **输入扇出继续收敛的 `exp_i` 类实验**：在 `exp_h` 的输入预寄存基础上，继续做输入寄存复制、按 `16+16` 子阵列分组、局部 bank 化布线友好组织，目标不是改变 `32-lane` 与 `II=1`，而是进一步降低“输入寄存到 32 个乘法器”的单拍扇出压力。
2. **乘法叶级本体优化的 `exp_j` 类实验**：既然关键路径已经稳定落到 `mult*_r`，下一步应尝试 Booth/部分积型乘法 RTL、或把 `16×16` 乘法明确重写成更物理友好的两级部分积与 CSA 结构，验证是否能把 `442.5MHz` 再往上推近 500MHz。
3. **带 tag 的流式回收原型**：独立模块已经是长流水，真正限制系统表现的是当前 core 没有把这条流水隐藏起来。因此应做一个带 `qpair/chunk` tag 的 QK slice 原型，让 `fa_attention_core` 可以连续发射多个 score-pair，再按 valid/tag 回收部分和。这类实验本身不一定改变 leaf STA，但对系统周期至关重要。

其次看 Norm。`exp_d` 通过高低半字部分积，把频率从约 `264MHz` 提升到 `360.8MHz`，说明该路径仍有结构空间，但它和 QK 不同：Norm 的主问题不是单一超宽扇出，而是**64bit 累计量 × Q16.16 倒数**后在同一路径上完成重组、舍入与饱和。因此下一轮实验建议集中在：

1. **更细粒度部分积 + carry-save 累加**：把当前 `pp_lo/pp_hi` 再细分为更规整的部分积树，并将最终 CPA 尽量后移，避免在单拍内同时完成过长的乘法重组。
2. **符号/绝对值/饱和路径解耦**：将 sign handling、rounding 和 saturation 明确拆到独立末级，验证当前关键端点是否其实卡在“乘积重组 + 饱和判断”的混合逻辑上。
3. **系统级 overlap 友好版本**：对 Norm 而言，未必一定要把 leaf 本身硬推到 500MHz 才有价值。若能把倒数请求更早发起、把 normalize chunk 与写回重叠，系统收益可能大于继续单独深挖 leaf STA。因此建议增加一类“保持 `exp_d` 叶结构、但改变 core 发射节奏”的系统实验。

综合来看，QK 更适合继续沿“叶级继续压关键路径 + core 做流式 tag 回收”双线推进；Norm 则更适合做“适度继续拆 leaf + 更强调系统 overlap”的组合策略。若只按优先级排序，下一步仍应先做 QK，再做 Norm。

#### 10.3.3 功耗分析

当前流程尚未形成完整的向量驱动功耗报告，因此本节只能给出定性分析而不提供签核级数值。一般而言，QK 点积模块由于具有大量并行乘法器和较宽寄存器阵列，是最可能同时成为面积与功耗热点的单元。归一化模块虽然频率较低，但 64bit 数据路径同样会带来不低的切换活动。Online Softmax 模块的面积和切换范围都相对较小，因此在总功耗中的占比预计不会像其时序重要性那样突出。待后续引入更稳定的门级网表与活动文件后，可再补充 VCD/SAIF 驱动的动态功耗分析与静态泄漏分析。

### 10.4 DRC \& LVS 验证

基于 Cadence 的完整后端尚未开展，因此目前没有可报告的 DRC 与 LVS 结果。现阶段使用 Yosys+iEDA 的目的主要是进行中前端结构收敛，而不是替代完整签核流程。后续若项目进入版图阶段，应在统一工艺库和约束环境下补齐版图生成、DRC、LVS、IR drop 和功耗完整报告。

### 10.5 总结

基于 icsprout55 的当前工作已经足够支持一个明确判断：项目的中前端热点和优化方向已被较清晰地定位。倒数与 Online Softmax 路径已经证明能够通过适当流水化达到或超过 500MHz；Normalization 有改善但优先级次之；QK 路径在本轮通过全流水乘法—加法树重构后已经被显著推进到 400MHz 以上，但仍是距离 500MHz 最近却也最难完全闭合的关键瓶颈。基于 Cadence 的完整物理实现尚未启动，但这并不妨碍当前基于 pre-P\&R 的结果对主线架构演进产生直接指导价值。

### 10.6 自评：`syn/` 覆盖完整性与自顶向下 PPA 估算

本小节仅用于自评，不作为正式报告对外展示内容。与前一版报告相比，本轮最大的变化不是“又多做了几个实验”，而是把真正已经被主线实例化的实验结构整理回了当前 RTL 命名体系：`fa_qk_dotprod_slice` 与 `fa_o_normalize_block` 现在已经分别对应 `exp_h` 与 `exp_d`；online softmax 也已经从 archived `pair` 切回 `ctx` 家族；`fa_dma_reader`、`fa_dma_writer` 与 `fa_perf_counters` 也已经补齐当前主线的直接 STA 结果。因此，`syn/` 对当前有效 leaf RTL 的覆盖已经明显强于上一版审计时的状态。

其次，从主线实例化关系看，当前 `fa_attention_ip_top` 直接例化 `1` 个 `fa_axi_lite_regs`、`1` 个 `fa_perf_counters`、`1` 个 `fa_dma_reader`、`1` 个 `fa_dma_writer` 与 `1` 个 `fa_attention_core`；`fa_attention_core` 内部再直接例化 `1` 个 `fa_qk_dotprod_slice`、`ROW_PAR=2` 个 `fa_mul_sat_q8_8`、`ROW_PAR×D=2D=128` 个 `fa_online_softmax_ctx`、`1` 个 `fa_recip_nr_q16_16` 与 `1` 个 `fa_o_normalize_block`。这里必须强调：`2D=128` 个 `ctx` 实例是本轮为了把 `ctx/exp_d` 功能恢复到主线而采用的**直接复制接法**，它不是最终 PPA 口径下希望长期保留的系统结构。

为了得到可用的 top-down 粗估，本报告继续采用“逻辑功能块 × 当前最佳候选模块面积”的保守方法，对**未来真正调度闭环后的主线**做一个结构下界估计，而不是把当前临时 `128×ctx` 接法直接乘进面积。参与估算的单模块面积分别取：`fa_axi_lite_regs=4399.64`，`fa_mul_sat_q8_8=4469.36`，`fa_recip_nr_q16_16(exp_c)=60594.24`，`fa_online_softmax_ctx(exp_d)=27216.28`，`fa_o_normalize_block(exp_d)=238672.84`，`fa_qk_dotprod_slice(exp_h)=286906.48`。按 `1×AXI-Lite + 2×mul_sat + 1×recip + 1×softmax + 1×normalize + 1×QK` 相加，可得到一个“面向未来合理主线结构、只覆盖主要已知计算块”的面积下界：

$$
4399.64 + 2\times 4469.36 + 60594 + 27216.28 + 238672.84 + 286906.48 = 626727.96.
$$

这个 `626727.96` 只能视为**核心已知块的面积下界**，因为它还没有计入 `fa_attention_core` 本身的控制逻辑、`fa_dma_reader`、`fa_dma_writer`、`fa_perf_counters`、顶层 glue logic，以及更重要的片上 buffer / 寄存阵列在完整顶层中的真实物理代价。换言之，如果未来把 `exp_h + exp_d + exp_d + exp_c` 这组最佳候选真正集成进主线，那么完整顶层的面积只会比这个数字更高，不会更低。

从时序角度看，这个自评揭示了一个更清晰的现实：当前主线最关键的“已吸收优化结构”已经从实验态转成了正式 RTL，而且 `QK` 与 softmax 的 system-level overlap 也已经兑现到当前 `main` 的实测周期上。具体来说，当前主线 full-run 已读回 `cycles=85928`、`cs_dp_run_cycles=66560`、`cs_softmax_prep_cycles=32768`；这说明问题已经不再是“高频候选模块是否被 core 以正确节奏使用”，因为这一点已经在当前主线中基本解决。因而后续若要把自评真正做扎实，优先级应转向：第一，补跑 `fa_attention_core` 与 `fa_attention_ip_top` 的直接综合，并重新核对 cycles / PPA；第二，针对当前 128 个 `ctx` 叶实例的面积与布线代价做更系统的 top-down 审计；第三，再把长序列、padding、multi-head 与 task queue 等 bonus 方向工程化落地。


## 10.7 0324 PPA 阶段结论（跨分支）

0310 的 PPA 结论主要针对 Q8.8 主线 leaf；0324 需要补充“哪些分支已进入可比 PPA 阶段，哪些仍是功能原型阶段”。

### 10.7.1 Q8.8 主线（可比阶段）

Q8.8 主线仍是当前唯一具备较完整系统口径的 PPA 参考：

1. 周期、误差、DMA、perf counters 都已闭环；
2. leaf STA 已有多轮结果；
3. 具备明确的系统瓶颈解释。

因此，若需要对外提供“当前 IP 的可信 PPA 数字”，仍应以该线为主。

### 10.7.2 Bonus 分支（非同等级 PPA）

- `exp/padding-mask-s512`：系统功能闭环成熟，但尚缺与 baseline 同深度的综合对照矩阵；
- `exp/bonus2-mha`：周期线性可解释，但并行化前提下的面积/时序收益尚未展开；
- `exp/bonus9-task-queue`：控制面扩展明显，PPA 影响主要在寄存器与控制逻辑，不在算术热路径；
- `exp/bonus1-bf16` 与 `exp/int8-fp8-bootstrap`：当前重点仍在算法/结构可运行性，尚未进入与主线同口径的工艺级比较。

结论：目前不能把低精度分支的“局部模块可跑”直接外推为主线等价 PPA 结论。

## 10.9 面向 500MHz 的下一阶段建议（系统视角）

在 0310 版中，500MHz 讨论主要集中在 leaf；0324 阶段建议把目标拆成双层：

1. leaf 层：继续压 QK/Norm 关键端点；
2. system 层：避免把 leaf 频率收益被调度气泡和数据搬运抵消。

重点动作：

1. 对 `fa_attention_core` 和 `fa_attention_ip_top` 补跑直接综合，形成 top-down 时序证据；
2. 量化 queue/multi-head/s512 分支对控制逻辑面积和关键路径的影响；
3. 对 `valid_len` 场景补充 DMA 裁剪实验，观察 bytes/cycle 改善幅度。

若不补这三项，下一轮 PPA 仍会停留在“leaf 很强，但系统收益不可量化”的阶段。

## 10.10 0324 小结

当前 PPA 可信度排序：

1. Q8.8 baseline 主线：最高；
2. `S=512/valid_len/multihead/queue` 系统扩展：中等（功能强，PPA 对照待补）；
3. BF16/FP16 与 INT8/FP8：原型验证为主，PPA 结论暂不对外外推。

这一定义有助于避免在报告中把“研究原型性能”误写成“可交付 IP 性能”。
