## 7. 算法实现架构建模

### 7.1 周期精确的 CModel 建立

`cmodel/` 目录中的 C++ 工程承担两类工作：第一类是精度对照，第二类是吞吐与周期建模。其文件组织为 `attention_math.cpp`、`attention_kernels.cpp`、`attention_experiment.cpp`、`attention_lib.cpp` 和公共头文件 `attention_core.hpp`。其中，数学文件实现 fixed-point 算术与近似函数，内核文件实现 attention 计算流程，实验文件实现多种模式扫描、阶段误差分解和 compute-only 架构模型，而库文件则把这些功能组织为可执行工具。

该 CModel 的重要价值并不只是“再写一份软件版 attention”，而是在于它提供了严格对齐 RTL 结构的多种模式。例如 `rtl_strict` 模式沿用 PWL exp、NR reciprocal 和 fixed-point 位移链路；`rtl_real_exp`、`rtl_real_exp_float_norm` 则逐步替换局部算子，用于判断误差究竟来自哪里；`run_stage_decomp` 能对各个算子阶段分别做 MAE、MaxAE 和 RMSE 统计；`run_compute_cycle_model` 则能够在不真正写出 RTL 的前提下，对不同 lane 数、row 并行数和是否引入 NoC 的架构做周期估算。

### 7.2 精度/吞吐量建模及优化

精度建模部分的关键结论前文已经讨论：`acc` 是主导误差源，而不是 `exp` 本身。吞吐量建模部分则给出了另一个很重要的系统性判断。以 `docs/data/20260304_compute_cycle_models_s256d64.csv` 为代表的结果显示，当采用 `fixed_flow_l32_norm8_row2` 时，compute-only 周期约为 `100,608`；若将 row 并行进一步扩大到 4，则可下降到 `51,328`；而引入简单 NoC 后，虽然功能上更灵活，但附加的分发与同步开销会使总周期反而回升。因此，对于当前问题规模和当前设计阶段，固定指令流并行优先于引入额外网络结构，是一个更合理的工程决策。

### 7.3 测试结果

为了便于汇总，表 7-1 列出 CModel 中最具代表性的几组数据。

| 数据类别 | 代表结果 | 结论 |
|---|---|---|
| 阶段误差分解 `small-int + causal` | `acc` MAE=`135.58`，`norm` MAE=`1.865` | 误差主导来自累计与归一化 |
| 阶段误差分解 `gaussian + causal` | `acc` MAE=`464.11`，`norm` MAE=`33.44` | 高动态输入进一步放大累计误差 |
| 方案对比 `small-int + causal` | `acc_float_qout` / `acc_float_real_exp_qout` 可达标 | 证明累计精度是关键方向 |
| 计算周期模型 `fixed_flow_l32_norm8_row2` | `100608 cycles` | 说明当前 RTL 仍有进一步结构优化空间 |
| 计算周期模型 `simple_noc_l32_norm8_row4` | `71808 cycles` | NoC 并非当前规模下的必要条件 |

这些结果有两个直接意义。其一，CModel 不是与 RTL 相互独立的辅助代码，而是架构决策的重要支撑工具。其二，当前主线之所以能够在不牺牲正确性的前提下把周期降到十几万级，并不是凭经验试错，而是因为 CModel 已经提前揭示了哪些方向会有效、哪些方向虽然看起来高级但收益有限。


## 7.4 0324 CModel 扩展：从“对算子”到“对推理行为”

0310 阶段 CModel 的主要任务是解释 fixed-point 算子误差与周期；0324 阶段 CModel 的角色已经扩展为“推理后端稳定参考”。

### 7.4.1 mode 扫描结果

`inference/native/logs/cmodel_mode_sweep_20260320.log` 给出 0~18 模式扫描。关键模式如下：

- mode14: `mae_lsb=0.579468`, `max_abs_lsb=1`
- mode15: `mae_lsb=0.589640`, `max_abs_lsb=2`
- mode16: `mae_lsb=0.590007`, `max_abs_lsb=1`
- mode17: `mae_lsb=0.588460`, `max_abs_lsb=1`
- mode18: `mae_lsb=0.587321`, `max_abs_lsb=1`

该结果说明：在随机张量层面，mode15/16/17 与 mode14 的平均误差差距并不大；但端到端文本稳定性差异仍显著，意味着“随机向量 MAE”不足以单独预测推理可读性。

### 7.4.2 mode14 的角色变化

mode14（FA_CORE_COMPAT）从“候选模式”升级为“推理稳定基线”：

1. 常规 chat prompt 可读；
2. role prompt 与 sw 主干可对齐；
3. 吞吐保持可用（多组样本 decode `~10-21 tok/s`）。

因此当前建议把 mode14 作为所有 DPI/RTL 定位的参考底座。

### 7.4.3 mode15/17 的阶段性判定

mode15（FIXED_Q8_IMPROVED）与 mode17（dual-buffer chunk=8）的价值在于“逼近纯 fixed 路线”，但尚未达到替代标准。

代表结论：

1. K-smooth 可显著降低主流误差分布（`realdiff` 平均误差从 `46.5565` 降到 `19.6330`，`p95` 从 `393` 降到 `1`）；
2. 仍存在少量离群（`max_abs_lsb` 甚至升高），并在 role prompt 触发结构化异常；
3. 热点 guard（单点或多点）收益有限，说明问题是全链路耦合而非单点 patch 可解。

## 7.5 多级建模与验证漏斗

0324 实际形成了四层建模漏斗：

1. Level-1 算子级：mode sweep（随机张量）；
2. Level-2 chat 级：5 prompt 可读性与 tok/s；
3. Level-3 role 级：结构化 prompt 稳定性；
4. Level-4 logits/热点级：top-k、head heatmap、stage trace。

该漏斗的价值在于把“误差数值”和“生成质量”建立因果桥接，不再只停留在 MAE。

## 7.6 与 RTL 对齐的下一步

基于当前建模结论，RTL 对齐建议是：

1. 保持 mode14 作为 golden-like 对照；
2. 针对 mode15/17 热点层位（如 layer22/23, head1/8~13）导出 `m/l/acc/norm` 同名观测；
3. 做 merge 参数联合扫描（chunk、rounding、PV shift、round bias），按“首分歧 token 位置”排序，而非按单一 MAE 排序。

该路径比继续堆叠局部 guard 更有概率收敛到可替代 fixed 路线。
