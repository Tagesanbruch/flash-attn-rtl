## 11. 总结

### 11.1 已完成的题目要求功能性能指标

> **禁止显式存储完整注意力矩阵**

这一要求已经完成，而且是当前 RTL 架构的核心前提。`fa_attention_core` 中只保存 `q_buf[TQ][D]`、双 bank `k_buf/v_buf[TK][D]`、按 query row 维护的 `row_m[TQ]`、`row_l[TQ]`、`row_acc[TQ][D]`，以及最终的 `o_buf[TQ][D]`。整个设计中都不存在 `score[S][S]` 或任何等价的完整注意力矩阵缓存。也就是说，对每个新得到的 score，设计会立刻做缩放、online softmax 状态更新和 PV 累加，而不是先把一整行或整个 `S\times S` 分数矩阵写到片上再统一处理。

从数据流角度看，这一点和 FlashAttention 的原始动机一致：当前默认参数下，若显式缓存 `256\times256` 个 score，即使用 16bit 表示，也需要约 `128KB` 级别片上存储；而当前主线把片上主要存储压缩到 Q/K/V tile buffer 与 row context 上，主存储量约为 `56KB` 级别。换言之，本设计不是“没有做 attention matrix buffer 只是巧合”，而是**从存储组织一开始就排除了这条路线**。

> **必须使用在线（online）softmax**

这一要求已经完成。算法公式层面，主线始终按 online softmax 的递推更新 `m/l/acc`：当新 score 到来时，只基于上一拍的 `m/l/acc` 与当前 `(score, value)` 做状态推进。当前版本中，softmax 路径已切回 `fa_online_softmax_ctx` 家族；在 `fa_attention_core` 内部，当前不仅保留了按 lane 复制的 `ctx/exp_d` 叶模块，还通过 `SOFTMAX_CTXS=4`、batch 化 row-pair 调度与 tag 化回收把它真正纳入流式系统调度中。

功能验证上，当前重新回归后，`fa_online_softmax_ctx` 单模块 cocotb 通过，`fa_attention_core` 通过，`fa_attention_ip_top` 也再次通过。这说明 online softmax 不只是“算法文档里写了”，而是已经在当前 RTL 与顶层系统回归中闭环。与此同时，本轮新建文档 [docs/20260310_online_softmax_ctx_pair_base2_comparison.md](docs/20260310_online_softmax_ctx_pair_base2_comparison.md) 已专门把 `ctx/pair/base2` 的实现差异与数据关系梳理清楚，避免后续再混淆“当前主线结构”和“历史实验候选”。

> **必须分块（tiling）处理 K/V**

这一要求已经完成。主线默认参数固定为 `TQ=32`、`TK=64`，因此 `SEQ_LEN=256` 会被拆成 `8` 个 Q tiles 和 `4` 个 K/V tiles。具体实现上，主状态机 `ms` 先读入一个 `Q tile`，随后对全部 `K/V tiles` 做内层遍历；每处理一个 `K tile` / `V tile`，就在 `S_COMPUTE` 中把 score、softmax 与 PV 累加流式完成。这样既限制了片上 buffer 规模，又保证了 K/V 以 tile 为单位被重复搬运和计算。

选择 `TQ=32`、`TK=64` 的原因，也已经在 RTL 与理论分析里被量化：`Q tile` 为 `4KB`，`K tile` 或 `V tile` 各为 `8KB`，与当前 `128bit` 总线、每 beat `8` 个 Q8.8 元素的搬运粒度是匹配的。顶层 full-run perf 读回的 `DMA_RD_CMD_COUNT=136`、`DMA_RD_BEAT_COUNT=34816`、`DMA_WR_CMD_COUNT=8`、`DMA_WR_BEAT_COUNT=2048` 也与这套 tile 组织高度一致，说明 tiling 不是停留在结构图上的概念，而是已经在系统层真实发生。

> **输入输出必须采用 Q8.8 定点格式，并保证内部有足够累计精度**

这一要求已经完成。`Q/K/V/O` 都采用 Q8.8；QK 点积结果先在 Q16.16 域内累计，再通过 40bit 中间和送入缩放；row 级累计接口 `row_acc` 仍保留为 64bit；倒数模块使用 Q16.16。当前 streamed `ctx` 主线内部的 softmax leaf 使用 32bit `l/acc` 标量状态，随后由 core 写回 64bit `row_acc` 接口，并在 normalize 入口补齐当前主线所需的尺度对齐，因此整个数值链路已经在当前 `main` 上重新闭合。

验证层面，这条数值路径已经在 core/top cocotb 中被 fixed-point 参考和 FP32 参考同时审计。当前主线在修正 `acc -> normalize` 尺度口径后，顶层 full-run 再次读回：RTL 相对 fixed-q8.8 参考 `mae_lsb=0`、`max_err_lsb=0`，相对 FP32 参考 `mae=0.002499`、`max_err=0.006583`，说明当前 `main` 已重新满足赛题精度门限，并且 fixed-point 参考也已与当前 RTL 主线对齐。

> **必须提供 AXI-Lite 控制接口**

这一要求已经完成。`fa_axi_lite_regs` 提供 `CTRL/STATUS/CFG/Q_BASE/K_BASE/V_BASE/O_BASE/STRIDE_BYTES/SCALE/NEG_LARGE/CYCLES/PERF_*` 等寄存器窗口。顶层寄存器回归已覆盖：

1. 默认寄存器值；
2. `CTRL` 启动脉冲；
3. `STATUS` 中 busy / done-sticky / error 语义；
4. 基地址与 stride 配置；
5. perf counters 的读回窗口。

这意味着 host 侧已经可以把本 IP 作为标准的“配置—启动—轮询完成—读结果/读统计”设备来使用。

> **必须提供 AXI4 Master DMA 数据接口**

这一要求已经完成。`fa_dma_reader` 负责从外部内存搬运 Q/K/V tile，`fa_dma_writer` 负责把 O tile 写回外部内存。主线核心通过 `dma_rd_cmd_*` / `dma_wr_cmd_*` 只下发逻辑命令，而不直接操纵 AXI 五通道细节，这使 tile 调度与总线协议保持了清晰边界。

验证上，单模块 DMA 测试已经覆盖 burst、错误返回、长命令拆分等基本场景；顶层 full-run 中又进一步把命令数与 beat 数与行为级内存模型统计交叉校验。当前 full-run 再次读回的 `rd_cmd=136`、`rd_beat=34816`、`wr_cmd=8`、`wr_beat=2048` 与内存模型观测一致，说明 DMA 不仅“能搬”，而且其统计口径也可信。

> **必须形成完整的端到端 attention 计算闭环**

这一要求已经完成。当前主线顶层 `fa_attention_ip_top` 已经把寄存器配置、DMA 读写、tile 调度、QK 点积、online softmax、normalize 和写回全部连通。本轮在把 online softmax 切回 `ctx` 后，又重新完成了三层回归：

1. `fa_online_softmax_ctx` 单模块 PASS；
2. `fa_attention_core` PASS；
3. `fa_attention_ip_top` PASS。

因此，当前结构变化没有破坏主线功能闭环，这也是本轮先做恢复、再谈调度优化的前提。

> **性能指标完成情况**

在功能项上，以上要求都已经完成；在性能项上，当前 `main` 也已经形成统一口径。

当前顶层 full-run perf 读回为：`cycles=85928`、`busy=85928`、`cs_dp_run_cycles=66560`、`cs_score_done_cycles=32768`、`cs_softmax_prep_cycles=32768`。其中：

1. `QK` 的 `8` 拍流水延迟已不再对每个 score-pair 重复支付，而是按 batch 支付；
2. `ctx` 的 `4-context` 交错能力已被当前主线调度真正利用；
3. `score retire`、`softmax issue` 与 `QK issue` 已发生重叠；
4. 最终总周期显著低于 baseline 要求的 `<300k cycles`。

因此，当前项目在性能层面的结论已经从“高频 leaf 能工作，但 system 仍未闭环”，转变为：

> **当前唯一活动主线 `main` 已经完成周期与精度双闭环，下一步工作的重点应从“主线达标”转向“bonus 扩展能力、分支管理与更完整 PPA 收敛”。**

## 11.4 当前最重要的“已知事实”

1. baseline 核心指标稳定：`85928 cycles` 与既有精度口径保持不变。
2. `S=512` top/IP 闭环已成立，但周期约 `307024`，不应与 baseline 目标混写。
3. `Q6.10/Q4.12` 当前属于外部格式桥接，不代表内部全链路多精度。
4. MHA 顺序版已展示良好线性缩放，但并行收益仍待架构重构。
5. task queue 已完成 true FIFO 形态与异常语义，具备进一步系统化条件。
6. mode14 已成为推理稳定参考；mode15/17 仍在“可读性改进但未替代”阶段。
7. BF16/FP16 与 INT8/FP8 分支均有实质进展，但仍属并行研究线，暂不并入 baseline 口径。
