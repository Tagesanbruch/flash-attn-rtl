
# FlashAttention IP 设计、验证与综合报告

## 1. 简介

本文档给出当前 FlashAttention-style SDPA 加速器 IP 的完整设计说明、验证闭环、建模方法以及综合结果总结。设计目标面向赛题给定的单 batch、单 head、自注意力场景，输入输出数据格式采用 Q8.8 定点表示，目标问题规模为 $S=256$、$D=64$，并在实现中显式满足 online softmax、K/V tiling、禁止显式存储 $S\times S$ 注意力矩阵、AXI-Lite 配置接口和 AXI4 Master DMA 数据接口等要求。

当前主线 RTL 已形成可运行的顶层系统。系统中包含 AXI-Lite 配置寄存器、AXI DMA 读写通路、片上 tile buffer、在线 softmax 状态维护、QK 点积与 PV 累加、归一化输出以及性能计数器。围绕这些功能，仓库同时建立了 cocotb 回归环境、Verilator C++ 参考测试路径、周期精确 CModel、模块级综合与静态时序分析流程。因此，本项目的工作不再停留于算子级数学原型，而是已经进入“结构可运行、验证可复现、性能可量化、综合可分析”的工程阶段。

截至 2026-03-11，仓库当前唯一活动主线 `main` 的核心结果为：端到端 RTL 在默认参数下已经达到 $85{,}928$ cycles 的总延迟量级，并保持与 fixed Q8.8 参考逐点一致、与 FP32 参考之间 $\text{MAE}=0.002499$、$\text{MaxAE}=0.006583$ 的误差水平。与此同时，模块级独立实验已经明确定位出 leaf 级 PPA 边界：Online Softmax `ctx/exp_d` 超过 $500\text{MHz}$，QK 路径 `exp_h` 达到约 $442.5\text{MHz}$，倒数模块也超过 $500\text{MHz}$。这说明当前设计不仅已经满足 baseline 提交约束，而且已经完成一次从“高频 leaf 恢复态”到“system-level overlap 真正闭环”的主线收敛。

本文将从整体进度、算法与架构、附加总线模块、功能验证、CModel、LLM 接入思路以及综合实现七个层面进行系统陈述。行文中尽量保持论文式的展开方式，对关键公式、时延估计、带宽估计与实验指标均给出完整说明。


## 1.1 0324 版本说明（相对 0310 的更新边界）

本报告在 2026-03-24 的更新目标不是重写 baseline，而是把 2026-03-11 到 2026-03-24 两周内的跨分支工作统一收敛为可审计、可引用、可复现实证。当前仓库仍以 `S=256, D=64, Q8.8, 单 batch, 单 head` 的 baseline 口径为核心，baseline 主线的关键数值口径没有变化：`cycles=85928`、`rtl vs fixed-q8.8` 逐点一致、`rtl vs fp32: MAE=0.002499, MaxAE=0.006583`。但在 baseline 外，已经并行展开多条 bonus 与研究线，且这些分支已形成可量化成果。

0324 版的关键区别在于：

1. 不再只描述 `main` 单线状态，而是明确给出分支图谱、每条分支的提交与改动规模、功能成熟度。
2. 对 0311 之后文档做全量吸收，不仅覆盖 `mode15/fpga` 路线，也覆盖 `padding-mask-s512`、`bonus2-mha`、`bonus1-bf16`、`int8-fp8-bootstrap` 的文档与结论。
3. 在“周期/误差”之外补上更完整的吞吐计算口径：`attn/s/GHz`、`GOPS/GHz`、`bytes/cycle`、`K/V` 流量占比。
4. 对“已完成”和“仍在实验”的边界做更严格切分，避免把原型结果误写成主线能力。

## 1.2 数据来源与口径统一

本版采用三类证据源交叉校验：

1. 代码与分支证据：`git branch -a`、`git log main..branch`、`git diff --shortstat main..branch`。
2. 文档证据：`docs/` 下 20260311 之后所有日期文档（含其他活动分支中的同日期文档）。
3. 运行/日志证据：`inference/native/logs/` 的模式扫描、prompt 回归、热力图与差分日志。

口径上统一遵循：

1. baseline 合规性以题目 `problem.md` 为准；
2. RTL 一致性优先看 `rtl vs fixed-like`；
3. 算法质量优先看 `rtl/cmodel vs fp32`；
4. 推理可用性不以 MAE 单独判定，必须同时看 decode token 行为与 role prompt 结构稳定性。

## 1.3 当前仓库的阶段定位

截至 2026-03-24，项目阶段可描述为“baseline 已收敛，bonus 进入分支化并行推进，推理接入转入数值稳定性攻坚”。

1. baseline：可提交且稳定。
2. 系统扩展（Bonus 2/3/4/5/9）：已有不同成熟度成果，其中 `3/4/5` 与 `9` 已有较完整 RTL+回归链路，`2` 已有标准 MHA 顺序版。
3. 低精度拓展（Bonus 1/7）：已完成 BF16/FP16 和 INT8/FP8 的原型与分阶段报告，但与 baseline 同等级的系统闭环尚未完成。
4. LLM 接入：DPI 与 cmodel 后端均已打通；cmodel 已恢复可读推理，DPI 仍受数值放大导致的分布坍缩约束。

因此，0324 报告不再把问题简化为“周期是否达标”，而是把重点转向“多分支成果如何归并成后续可执行路线”。
